# Handoff: корпоративный почтовый клиент под Stalwart (JMAP)

Дата: 2026-10-17. Источник: обсуждение выбора почтового сервера и клиентов.

## 1. Контекст и принятые решения

- Сервер: **Stalwart** (Rust, один бинарник: SMTP/IMAP/JMAP/CalDAV/CardDAV/WebDAV, антиспам, LDAP/OIDC). [факт]
  - Сейчас v0.16.x; 1.0.0 обещан «около октября 2026», ещё не вышел на 16.10.2026; до 1.0 апгрейды ручные, вендор советует не обновляться без нужды. [факт]
  - Внедрение в прод — после 1.0. [решение]
  - Thundermail (сервис Mozilla/Thunderbird) построен на Stalwart (репо thunderbird/mailstrom) — Thunderbird будут вылизывать под этот сервер. [факт]
- Клиенты:
  - Mac/iOS — штатные Apple Mail/Calendar/Contacts по IMAP/CalDAV/CardDAV, не трогаем. [решение]
    - Известная проблема: Apple Calendar не показывает «Доступность» на Stalwart — похоже на capability-advertisement на стороне сервера (форум Stalwart). [факт] [проверить]
  - Основной десктоп — **Thunderbird ESR** (IMAP/CalDAV/CardDAV/LDAP, RFC 6638 free/busy умеет). [решение]
  - **Этот проект**: собственный «good enough» клиент под Windows (Linux — бонус), JMAP-only, без конкуренции с миром, внутреннее использование. [решение]
- Отвергнуто (и почему):
  - Outlook по IMAP — теряет планировщик, GAL-автодополнение, общие ящики, серверные правила. Outlook-плагин (COM/PST-sync или MAPI provider) — срок годности до конца classic Outlook (~2029), хрупок к обновлениям, Google закрыла свой GSSMO. [оценка]
  - Carbonio — ~30 компонентов, 6+ БД, «лоскутность». Grommunio — Exchange-replacement с MAPI, но ядро + PHP-обвязка; запасной вариант, если Outlook окажется must-have.
  - ArtCraft Crafting Apps — Rust-клоны Adobe/MS, почтового клиента нет, альфа. Следить, не опираться.

## 2. Цель и границы продукта

Цель: простой клиент почта+календарь+контакты, который даёт то, чего нет в Thunderbird/Outlook-по-IMAP — **занятость коллег и планирование встреч** — и нормально общается с внешним миром (Google/Exchange) через стандартные приглашения.

### MVP (в объёме)
- Аккаунт: autodiscover `.well-known/jmap`, вход по паролю и OAuth (Stalwart реализует mailmaint OAuth-профиль для public clients). [факт]
- Почта (RFC 8621): папки, список/тред, чтение, ответ/ответ всем/пересылка, вложения, флаги/прочитано, перемещение/удаление, поиск (серверный Email/query), push (EventSource / WebSocket RFC 8887).
- Композер: Markdown → multipart/alternative (text/plain + text/html), цитирование, подпись, inline-вложения.
- Календарь (JMAP Calendars, draft; Stalwart реализует): просмотр/создание/правка, приглашения iTIP через JMAP + iMIP по почте для внешних, принятие/отклонение, **занятость участников** (`Principal/getAvailability` или аналог). [проверить точное имя метода и поддержку в Stalwart]
- Контакты (RFC 9610 JSContact) + корпоративный справочник по LDAP с автодополнением.
- Локальный кэш (SQLite) для офлайн-чтения и быстрого старта; дельты через `*/changes`.

### Вне MVP
Правила/фильтры (Sieve — через веб-клиент), теги, PGP/S-MIME, темы, бронирование ресурсов (у Stalwart нет автоакцепта с проверкой конфликтов — [факт]), mailto:-регистрация, автообновление, Mac/iOS.

## 2a. Дизайн: визуальный аналог classic Outlook [решение]

Цель — чтобы сотрудник, пересевший с Outlook, не переучивался. Clean-room: повторяем раскладку, поведение и горячие клавиши, не используем иконки, шрифты, названия и ресурсы Microsoft.

- Общая раскладка: левая навигация (Почта / Календарь / Контакты внизу или сбоку, как в Outlook), три панели: дерево папок — список писем — область чтения; переключение чтения справа/снизу/выкл.
- Список писем: группировка по дате, превью 1–2 строки, флаг/непрочитано/вложение, треды сворачиваемые, сортировка/фильтр «непрочитанные» одной кнопкой.
- Область чтения: шапка письма как в Outlook (От/Кому/Копия/дата), кнопки Ответить/Всем/Переслать на месте, вложения полосой под шапкой, баннер «удалённые картинки заблокированы».
- Композер: отдельное окно или вкладка, поля Кому/Копия/Скрытая, автодополнение из LDAP и контактов, панель форматирования минимальная (Markdown-ввод, превью).
- Календарь: виды День/Рабочая неделя/Неделя/Месяц, мини-календарь слева, список календарей с чекбоксами, наложение нескольких календарей. Окно встречи — по образу Outlook: вкладки «Встреча» и **«Помощник планирования»** с сеткой занятости участников (ключевая фича).
- Контакты: карточка контакта + список; корпоративный справочник отдельной «адресной книгой».
- Горячие клавиши Outlook: Ctrl+N, Ctrl+R, Ctrl+Shift+R, Ctrl+F (переслать), Ctrl+E (поиск), Ctrl+1/2/3 (почта/календарь/контакты), Del, Ctrl+Q/U (прочитано/непрочитано).
- Визуал: светлая тема по умолчанию, плотная (не «воздушная») вёрстка, системный шрифт Windows, тёмная тема — позже. Никаких лент (ribbon) — простая панель команд.

## 2b. Принципы (унаследованы из проекта filenav) [решение]

1. **Чистый Rust.** Без Electron, без webview для оболочки, без JS-рантайма.
2. **GPU-рендер через wgpu → DX12 на Windows** (Vulkan на Linux). Скорость отрисовки и отклика — критерий качества: список из 50 тыс. писем скроллится без рывков, переключение папки/письма — мгновенно.
3. **Хоткеи на всё.** Любое действие достижимо с клавиатуры; мышь — опция. Набор клавиш — Outlook-совместимый (раздел 2a) плюс vim-подобная навигация в списках (j/k) как дополнение.
4. **Экономия памяти.** Целевой бюджет [оценка]: ≤150 МБ RSS с открытым ящиком 50 тыс. писем и календарём; письма и вложения — лениво, из SQLite-кэша; никаких «держим всё в памяти».
5. Быстрый холодный старт (< 1 с до списка писем из кэша), минимум зависимостей, один исполняемый файл.

## 3. Стек (предложение, утвердить на планировании)

- **Ядро (Rust):** `jmap-client` (JMAP core/mail/WebSocket), `mail-parser`, `mail-send`/`mail-builder`, `calcard` (iCalendar/vCard) — все от автора Stalwart; `rusqlite` для кэша; `tokio` для сети. [факт — крейты существуют; версии и покрытие Calendars/Contacts — проверить]
- **UI (Rust + wgpu), кандидаты — выбрать на спайке первой недели:**
  - `egui` (eframe/wgpu) — самый быстрый старт, immediate-mode, отличная производительность списков; слабее с типографикой и сложными раскладками.
  - `iced` — retained/Elm-архитектура, wgpu, зрелее по виджетам.
  - `gpui` (движок Zed) — лучшая производительность текста, GPU-first, но API нестабилен и документации мало.
  - `Dioxus native` (рендер Blitz на wgpu/Vello, CSS-движок из Servo) — декларативный UI, тот же путь, что выбрал Stalwart для своего webmail; молодой.
- **Рендер HTML-писем — решено: без движка, подмножество HTML → собственное IR** (раздел 3a). Webview (WebView2) и Blitz/Stylo — отвергнуты.
- **Композер:** Markdown в собственном редакторе (egui/iced text edit достаточно), генерация text/plain + text/html через `pulldown-cmark` + `mail-builder`; цитирование — из IR (раздел 3a).

## 3a. Безопасность рендера писем [решение]

Принцип: никакой возможности исполнения, никакого layout-движка, никаких внешних обращений. Базовое восприятие писем от людей не снижается — форматирование Outlook/Gmail/Apple Mail это 5–6 свойств, которые мы сохраняем.

**HTML → IR (белый список).**
- Парсер `html5ever` → обход DOM → IR = Markdown-подобный AST (совместимый с событиями `pulldown-cmark`). Один формат для входящих, отображения и ответа.
- Разрешённые элементы: `p br h1–h6 b strong i em u s a ul ol li blockquote pre code hr table tr td th img div span` (div/span — только как границы блоков/инлайна).
- Выбрасываются на этапе парсинга, не доходя до рендера: `script style iframe object embed form input button svg math link meta base`, все `on*`-атрибуты, комментарии, `<!--[if]-->`-условия.
- `a`: только `http(s):` и `mailto:`; href показывать при наведении; подсветка несовпадения видимого текста-URL и href; IDN → punycode видимо.
- `img`: только `cid:` из вложений письма, по умолчанию скрыты, включение по клику на письмо/отправителя; внешние `src` — никогда не загружаются (трекинг-пиксели не работают).
- Таблицы: простая сетка без вложенности; вложенные/layout-таблицы линеаризуются в текст. Outlook-вёрстка становится текстом — приемлемо.
- CSS: не парсится как CSS. Из `style=""` простым токенайзером берутся только: `font-weight` (bold), `font-style` (italic), `text-decoration` (underline/line-through), `text-align`. Переводятся в семантические марки IR. `color`, `font-size`, `display`, `position`, `visibility`, `opacity`, `background`, `url()`, `@import`, `@font-face` — игнорируются (ими прячут текст, накладывают фальшивые элементы, тянут сеть). Если позже захочется цвет/размер — только с нормализацией (контраст с фоном, размер в диапазоне).

**Песочница воркера.** Парсинг MIME/HTML и декодирование картинок — в отдельном процессе-воркере; UI получает по пайпу готовый IR и сырые RGBA через shared memory.
- Windows: AppContainer (lowbox-токен), Low IL, Job Object (запрет дочерних процессов, лимиты памяти/CPU, kill-on-close), `SetProcessMitigationPolicy`: DEP, ASLR, CFG, **Win32k syscall disable**, запрет не-Microsoft DLL; без сети.
- Linux: user namespaces + seccomp-bpf (bubblewrap-подход), Landlock для ФС.
- Картинки: крейт `image` только внутри воркера; форматы PNG/JPEG/GIF/WebP; WMF/EMF/TIFF/SVG — не поддерживаются.
- Вложения: никогда не открывать автоматически; превью только безопасных типов в воркере; остальное — ОС по явному клику пользователя.
- Поверхность атаки в итоге: `mail-parser` + `html5ever` + `image`, все memory-safe, все в контейнере без сети и win32k.

**Ответ/пересылка через IR.** Цитата = IR → Markdown с `>`; исходящее = text/plain (Markdown) + text/html из фиксированного набора тегов собственным генератором. Скрытый текст, CSS-трюки и пиксели из оригинала в цитату не попадают.

**Кнопка «Открыть в браузере»** — для редких маркетинговых писем, по явному действию пользователя, вне ответственности клиента.
- Платформа: Windows 10+ (DX12); Linux (Vulkan) из той же сборки. Mac — нет.
- **Отвергнуто:** Tauri/Electron-оболочка — противоречит принципам 1, 2, 4.

## 4. Что выяснить до старта [проверить]
1. Stalwart: какие JMAP capabilities объявляет текущая версия (`urn:ietf:params:jmap:calendars`, `:contacts`, `:principals`, `:websocket`, `:blob`), есть ли availability/free-busy в JMAP, как шлются scheduling-сообщения (`CalendarEvent/set` + sendSchedulingMessages?).
2. Состояние крейтов `jmap-client`/`calcard` под Calendars/Contacts (возможно, придётся дописывать типы).
3. Apple Calendar «Доступность» на Stalwart — воспроизвести, найти причину (нужно для Mac-пользователей, не для клиента).
4. Thunderbird free/busy против Stalwart — воспроизвести (это референс-поведение).
5. Дата выхода Stalwart 1.0 и изменения схемы — чтобы не писать кэш под уходящий формат.
