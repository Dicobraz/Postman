# План работ после спайка UI

Дата: 2026-10-18. Основание: `docs/UI-SPIKE.md` (вывод — gpui через gpui-kit) и разбор подхода ArtCraft
(WordCraft/GridCraft): библиотеки и движок текста не заимствуем, берём три идеи — слои с проверкой,
реестр команд, правило «не падать».

Порядок: сначала ворота, которые могут отменить выбор gpui, потом фундамент, потом перенос экранов.
Каждая фаза заканчивается проверкой на Windows.

## Фаза 0. Ворота gpui

Цель — подтвердить или отменить выбор до вложений в перенос. Провал ворот, который не лечится патчем, —
откат на egui (версия `app` готова) с отрисовкой текста письма своим движком.

| № | Что | Как проверяем | Успех |
|---|---|---|---|
| 0.1 | Хоткеи в русской раскладке | тестовая сборка: в строке состояния — полученная клавиша и сработавшее действие; Ctrl+E, Ctrl+1/2, Ctrl+Q/U, «о»/«л» | работают; иначе патч — перевод виртуального кода клавиши в латиницу, как в egui, и повтор |
| 0.2 | CPU в простое | патч `VSyncProvider`: поток спит, пока ни одно окно не просило кадр; `bench.cmd` | `idle_cpu_pct` ≤ 0,5 % |
| 0.3 | CPU при листании | профиль на Windows (gpui `profiler` или WPR) по двум сценариям: текущий и реалистичный — листание без открытия письма в каждом кадре; отделить нагрузку нашего кода от gpui | не хуже egui (≈ 45 % ядра) или понятная причина и патч |
| 0.4 | Ресайз и разворачивание на Intel | ручная проверка по `README.txt` архива | нет чёрных кадров и мерцания |
| 0.5 | Песочница на Windows | ✅ CI 19.10: все тесты песочницы зелёные на Windows с полной изоляцией (`4994089`: без консоли — запрет дочерних процессов блокировал conhost); осталось глазами на машине владельца | «полная» после `sandbox.cmd`, иначе «частичная» |

Итог фазы: запись «gpui — окончательно» в `docs/UI-SPIKE.md`, файл `docs/PATCHES.md` со списком наших
патчей gpui и статусом их предложения разработчикам.

### Патчи и upstream

- Держим только то, что патчим: крейт `gpui-pre-windows` в `third_party/` через `[patch]`, остальное — crates.io.
- Исправления gpui (хоткеи, VSyncProvider) — pull request в zed-industries/zed; компонентов — в longbridge/gpui-kit.
  Принятый патч выпадает из списка при обновлении gpui-kit.
- Не принятые — переносим на каждую новую версию gpui-kit. Замораживать версию не будем.
- Патч шейдеров — только для кросс-сборки из Linux, upstream не предлагается; уйдёт, когда заработает
  сборка на Windows (CI, нужен fxc.exe).

## Фаза 1. Фундамент (идеи ArtCraft)

Делается до переноса экранов, чтобы экраны сразу строились на нём. Применимо при любой UI-библиотеке.

**1.1 Слои с проверкой.** Таблица крейтов по слоям и проверка `cargo xtask layers` (или тест рабочей области
по `cargo metadata`): ниже слоя интерфейса нет зависимостей от gpui, egui, winit, rfd.

| Слой | Крейты |
|---|---|
| L0 | `ir` |
| L1 | `jmap`, `cache`, `compose`, `calendar`, `search`, `worker` |
| L2 | `core` (синхронизация, команды, адресная книга, файлы без диалогов) |
| L3 | `app-gpui`; `app` (egui) — запасной |
| вне | `demo` (данные для демо и тестов) |

Уже найдено нарушение: `core` зависит от `rfd` (диалоги «Сохранить как…» в `files.rs`) — диалоги
переезжают в слой интерфейса.

**1.2 Реестр команд.** Каждое действие пользователя — команда с идентификатором (`mail.reply`,
`mail.reply_all`, `mail.forward`, `mail.mark_read`, `calendar.new_meeting`…): название, хоткеи Outlook по
умолчанию, условие доступности. Из реестра:
- строятся действия и привязки клавиш gpui (действия gpui — тот же механизм, типизированный);
- кнопки, меню и подсказки хоткеев в интерфейсе;
- внешний вызов по идентификатору (внешние системы) — позже;
- тест: каждый хоткей Outlook из таблицы привязан, в том числе в русской раскладке.

**1.3 Правило «не падать».** В коде вне тестов нет `unwrap`/`expect`/`panic!` (сейчас 127 мест) — запрет
через `clippy::unwrap_used`/`expect_used` по крейтам, убираем постепенно, начиная с `core` и `cache`.
На каждое исправленное падение — регрессионный тест. Фаззинг: случайные последовательности команд
над демо-ящиком (инварианты: кэш читается, счётчики сходятся); входы воркера уже фаззятся враждебными
письмами.

**1.4 Чек-лист соответствия Outlook.** `docs/PARITY.md` собирается из реестра команд: функция, хоткей,
статус. Доля сделанного только растёт — проверяется тестом.

**1.5 Проверка интерфейса агентами.** Скриншоты без участия человека (Xvfb в контейнере, на Windows —
по возможности), а не управление окном нажатиями.

## Фаза 2. Перенос экранов в gpui

Порядок — по ценности для пользователя, каждый пункт на командах из 1.2:
1. Список: полоса прокрутки; ответ, ответить всем, переслать и их хоткеи.
2. Окно письма: поля с подсказками адресов, вложения, автосохранение, предпросмотр, закрытие с вопросом.
3. Область чтения: вложения, баннер картинок `cid:`, карточка приглашения.
4. Синхронизация с сервером (`postman_core::sync`) вместо демо-ящика, поиск.
5. Календарь на реальных данных, создание встречи, «Помощник планирования».

egui-версию не развиваем; удаляем после пункта 4, когда gpui её догонит.
