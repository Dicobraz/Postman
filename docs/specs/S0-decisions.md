# S0. Решения владельца

Источник правды по решениям: выше всех остальных документов. Новое решение — строкой сверху, с датой.

## 2026-10-23. Второй путь: стандарты и Exchange (on-prem) — сессия S7

Цель — по-прежнему Stalwart по JMAP. Второй путь — стандарты: IMAP + SMTP + CalDAV (scheduling, free/busy RFC 6638)
+ CardDAV, он же работает и со Stalwart. На переходный период — Exchange компании (on-prem, 2016+ через EWS, best
effort) только в том, чего стандартами не достать: календарь и ответы на встречи, занятость (`GetUserAvailability`),
GAL (`ResolveNames`); вход — Negotiate/NTLM через SSPI; почта Exchange — его IMAP/SMTP. Надстроек Microsoft нет (правила
Outlook, категории, флаги, OOF, задачи, общие ящики, streaming); к ним — только если понадобится. Чего у сервера нет —
не показывается (одно правило, `docs/specs/S7.md`). Несколько учётных записей — в существующем дизайне, без новых
экранов: группа в дереве папок, «От» выбирает учётку, календари всех учёток вместе с цветами владельца (S5-22), один
поиск, «Настройки → Аккаунты»; во вкладке встречи — поле «От» композера, по умолчанию — учётка календаря,
выбранного слева (ответы владельца на вопросы 2 и 3 S7). Заменяет решение 2026-10-20 №5 (IMAP/SMTP — бэклог).

Стенда Exchange не будет: проверка — на боевом Exchange «в разумных пределах», по правилам `docs/specs/S7.md` «Проверка
на боевом Exchange» (только тестовые учётки, без массовых операций, уборка после теста, письма только между тестовыми
учётками, настройки — только у тестовых учёток, GAL и занятость коллег — только чтение; адрес сервера и секреты —
только в локальном окружении владельца, тесты `#[ignore]` по переменным окружения). Стандарты — на стенде Stalwart.
Архитектура — ADR 0003 (модульное ядро: нейтральная модель и адаптеры) — принят. Открыт вопрос 1 S7: тестовые учётки
и включены ли на Exchange IMAP4 и SMTP-приём от клиентов.

## 2026-10-22. Размер exe: бюджет 48 МиБ, оптимизация перед выпуском

После замера S5-32 (`postman.exe` 47,33 МиБ при бюджете 45, `docs/SIZE.md` «После S5 и S6»): бюджет `postman.exe` —
**≤ 48 МиБ** (не скачком на 10 %, а по факту с малым запасом); воркер — ≤ 10 МиБ, `panic = "unwind"` — как были
(`docs/SIZE.md` №1, №6). Размер оптимизируем один раз, когда функции готовы: пункт «Размер exe: оптимизация» — в
проверках перед выпуском (`docs/SIZE.md` «Перед выпуском»).

## 2026-10-22. Цвета: ответы владельца по S5-31 (#67)

Тёмная тема: точка графита #CDCDCD, серого #5C5C5C — ΔE2000 ≥ 25 ко всем цветам без исключений. Выделенная строка списка — нейтральное «выбранное» (#EBEBEB, тёмная
#3A3A3A) с полосой акцента слева; синяя #DFF0FF — только метки и кнопки. Категорий — пять цветов; шестую при занятых
цветах не добавить (строка в редакторе), новые цвета — позже через дизайн. «Ждёт ответа» в календаре — пунктирный
контур без заливки, как в `DESIGN.md`. Розовый бренда — и у «Тендеров» (исключение ΔE к красному безопасности).

## 2026-10-22. Задачи: хранение и поручения — по рекомендации S6-01

По итогам стенда S6-01 (`docs/specs/S6.md`, раздел S6-01; `docs/STALWART.md` п. 37–42) — по рекомендации:

| № | Вопрос | Решение |
|---|---|---|
| 1 | Где хранить задачи (S6 решение 1) | В календаре сервера: JMAP `CalendarEvent` с `"@type": "Task"` (JSCalendar 2.0) — тот же VTODO, что видят CalDAV-клиенты. Свои поля — `X-POSTMAN-*` в `iCalendar.properties`. CalDAV-модуля, FileNode и локального хранения нет |
| 2 | Формат поручения (S6 решение 2) | iTIP по VTODO, как приглашения: REQUEST, REPLY, CANCEL; COUNTER и комментарии шагов — письмом (сервер их не сохраняет). Подробности (своё письмо REQUEST, наблюдатели) — S6-09 |

## 2026-10-21 (вечер). Цвета — свои токены `docs/DESIGN.md`, не «общие цвета» Fluent 2

Владелец сравнил на холсте календарь в двух вариантах и выбрал вариант с токенами `DESIGN.md` («Токены цвета»).
Заменяет решение S5 №5 (палитра категорий — «общие цвета» Fluent 2). Категории: Клиенты — синий, Команда — зелёный,
Тендеры — розовый бренда, Пентест — графит, Сервисы — серый; бирюза не используется. Почти одинаковые оттенки сведены
к одному токену (таблица). «Ждёт ответа» в календаре — пунктирный контур без заливки (`DESIGN.md` «Календарь»). Код (`roles.rs`, `postman_core::palette`)
приводится к таблице отдельной задачей S5.

## 2026-10-20. Пересмотр дизайна и состав MVP

Пересмотр дизайна по ADR 0002 выполнен: утверждённые экраны и правила — `docs/DESIGN.md`.

| № | Вопрос | Решение |
|---|---|---|
| 1 | Правила почты (были вне MVP, «через веб-клиент») | В MVP: редактор в «Настройки → Правила», хранение — Sieve на сервере (capability `sieve` есть) [проверить на стенде] |

## 2026-10-19. Расхождения с базисом Pets

| № | Расхождение | Решение |
|---|---|---|
| 1 | Визуальный язык: в ТЗ — classic Outlook, в базисе — Fluent | Каркас и раскладка — как у Outlook, цвета, шрифты и тосты — по Fluent (ADR 0002). Позже отдельно пересмотреть дизайн и упростить: Outlook слишком тяжёлый |
| 2 | Модальный вопрос при закрытии окна письма (egui) | По базису: подтверждение одной строкой в самом окне. В gpui — сразу так |
| 3 | Бюджеты: exe 19–26 МБ при < 15, первый кадр 0,9–1,1 с при < 250 мс, CPU в простое ~2 % при 0 % | Бюджеты базиса не догма: каждый проект считает свои на этапе ТЗ. Бюджеты Postman — `docs/HANDOFF.md` §2c |
| 4 | CI только на Windows, в базисе — Windows, Ubuntu, macOS | Windows — основа, остальные ОС — по запросу. Решения, не завязанные на ОС, учитывают и их: код вне `sys`-модулей кроссплатформенный |
| 5 | Нет инфраструктуры базиса: локализация EN+RU, тосты, единственный экземпляр, журнал Windows | Взять готовое из Урфина в фазе 1, вместе с реестром команд (`docs/PLAN.md` 1.6) |
| 6 | Процесс: ветки, PR на задачу, спеки | По базису со следующей задачи (0.1, хоткеи): задача = ветка `sX/NN-кратко` = один PR, спека — `docs/specs/Sx.md` |

ADR 0001 (gpui вместо egui) — принят условно; окончательно — выше, после ворот фазы 0.
