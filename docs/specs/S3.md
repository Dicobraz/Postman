# S3. Перенос экранов в gpui (фаза 2 `docs/PLAN.md`)

Цель — довести интерфейс на gpui (`app-gpui`) до рабочего клиента: письмо пишется и отправляется, ответы и
пересылка, вложения и приглашения в области чтения, живой ящик на сервере вместо демо, календарь на реальных
данных. egui-версия (`app`) — образец поведения, код не переносится как есть. Задача = ветка `s3/NN-кратко` =
один PR; на фундаменте S2: команды из реестра, тексты через Fluent, «не падать», view с кэшем, тосты вместо
модальных окон, снимки `--screens` для проверки.

Стенд Stalwart готов (S2-08) — задачи с сервером проверяются тестами `crates/core/tests/stand.rs` и руками на
стенде, а не только на демо-ящике.

| Задача | Что | Зависит от | Статус |
|---|---|---|---|
| S3-00 | Экран — модули (`list`, `folders`, `reading`, `bar`, `mailer`), тексты — файл на часть | — | готово |
| S3-01 | Окно письма: адреса с подсказками, вложения, автосохранение, предпросмотр, отправка | S3-00 | |
| S3-02 | Ответ, ответить всем, переслать, удалить; полоса прокрутки списка | S3-01 | |
| S3-03 | Область чтения: вложения, картинки `cid:`, карточка приглашения | S3-00 | |
| S3-04 | Живой ящик: учётная запись, синхронизация `postman_core::sync`, поиск на сервере, push | S3-00 | |
| S3-05 | Календарь на сервере: события, окно встречи, помощник планирования на реальной занятости | S3-04 | |

Порядок: S3-01, S3-03, S3-04 — параллельно (разные модули и файлы текстов); затем S3-02 и S3-05.
Ручные проверки — разделы в `docs/MANUAL-TESTS.md`, проходим с владельцем в диалоге после мержа.

## Общие правила задач

- Новая часть экрана — свой модуль и свой файл текстов `app-gpui/i18n/{ru,en}/<часть>.ftl` (в `TEXTS`).
- Новое действие — команда в реестре (`commands.rs`, название в `commands.ftl`), затем
  `POSTMAN_UPDATE_DOCS=1 cargo test -p postman-gpui parity`.
- Поток интерфейса не ждёт диск и сеть: хранилище, файлы и сервер — в фоне (`background_spawn`, поток sync).
- Подтверждения — строкой в самом окне, уведомления — тостами; модальных окон нет.
- В демо-режиме (`--demo`) всё, что требует сервера, не падает: тост «нужен сервер» или локальная заглушка.

## S3-00. Модули экрана

`main.rs` (985 строк) разрезан без изменения поведения: `list.rs` (список и окно строк), `folders.rs`,
`reading.rs`, `bar.rs`, `mailer.rs` (экран, действия, замер); в `main.rs` — запуск. Тексты —
`i18n/<язык>/app.ftl` и `commands.ftl`. Чек-лист Outlook (`parity`) ищет обработчики во всех модулях.

## S3-01. Окно письма

Как в classic Outlook (ADR 0002): новое письмо — отдельное окно (не модальное, основное окно работает).
- Поля «Кому», «Копия», «Скрытая», «Тема»; адреса — с подсказками из адресной книги
  (`postman_core::contacts`: контакты сервера и история переписки), разбор — `postman_compose::parse_addresses`,
  ошибочный адрес подсвечен.
- Текст — Markdown (`postman_compose`), предпросмотр переключением; подпись из Identity.
- Вложения: выбрать файлы (диалог ОС — L3, `rfd`), перетащить файлы в окно, убрать; размер и имя видны.
- Автосохранение черновика (раз в N секунд при изменениях и при закрытии) — команда `SaveDraft` синхронизации;
  в демо — локально.
- Отправка (`Ctrl+Enter`, `Alt+S`) — команда `Send`; ошибка — строкой в окне, окно не закрывается.
- Закрытие с несохранённым — строка в окне «Сохранить черновик? Да / Нет / Отмена», без модального окна.
- Команды: `mail.new` (Ctrl+N, уже есть), `compose.send`, `compose.attach`, `compose.preview`, `compose.close`.

Приёмка: тесты модели окна (поля → `Draft`, грязное/чистое, разбор адресов); снимок окна письма в `--screens`;
на стенде письмо уходит и приходит (тест `stand` уже есть для отправки).

## S3-02. Ответ, пересылка, удаление

- `mail.reply` (Ctrl+R), `mail.reply_all` (Ctrl+Shift+R), `mail.forward` (Ctrl+F) — окно письма с черновиком
  из `postman_compose::respond` (цитата, In-Reply-To/References, вложения оригинала при пересылке).
- `mail.delete` (Delete) — в «Удалённые» (из «Удалённых» — насовсем, подтверждение строкой).
- Полоса прокрутки списка; позиция сохраняется при смене папки туда и обратно.

## S3-03. Область чтения

- Вложения: список под шапкой (имя, размер, значок), «Открыть» и «Сохранить как» (`postman_core::files`,
  метка «из Интернета» — MotW), скачивание — в фоне.
- Картинки `cid:` — внутри письма (блоб вложения), внешние по-прежнему заблокированы (баннер есть).
- Карточка приглашения: когда, где, организатор, участники, мой статус; «Принять», «Под вопросом»,
  «Отклонить» — `postman_core::invite` (через календарь сервера, иначе письмом REPLY); итог — тостом.

## S3-04. Живой ящик

- Учётная запись: `POSTMAN_URL`/`POSTMAN_USER`/`POSTMAN_PASSWORD` (или `POSTMAN_TOKEN`), иначе — строка входа
  в окне (адрес сервера, логин, пароль); пароль — в диспетчере учётных данных Windows, на диск не пишется.
- `postman_core::sync` вместо демо: папки, письма, тела по требованию и предзагрузкой, флаги, push;
  события синхронизации → обновление view и тосты (ошибка, «нет связи»).
- Поиск: локальный индекс и сервер (`Search`), результаты — в списке, как сейчас.
- `--demo` остаётся для бенча, снимков и работы без сервера.

## S3-05. Календарь на сервере

- Неделя из `CalendarEvent/query` (повторения разворачивает сервер), свои календари.
- Окно встречи (новая — Ctrl+Shift+Q): тема, место, время, участники с подсказками, «Помощник планирования»
  на занятости из `Principal/getAvailability`; отправка — `sendSchedulingMessages` (S2-08).
- Открыть свою занятость коллегам (`share_calendar`) — настройка; без шаринга сетка пустая (см. `docs/STALWART.md`).
