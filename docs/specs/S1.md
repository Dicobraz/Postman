## S1-01. Хоткеи в русской раскладке

Риск из `docs/UI-SPIKE.md`: клавиша сочетания берётся через `MapVirtualKeyW(…, MAPVK_VK_TO_CHAR)`.
Проверка на стенде: для буквенных клавиш эта функция отдаёт латиницу в любой раскладке (VK_E → «E»
и в русской), символ раскладки gpui берёт отдельно через `ToUnicode` (`key_char`). Привязки строятся
по той же таблице. Патч gpui не нужен.

Проверка — `scripts/keys-ru.ps1`: запускает `postman-gpui` с `POSTMAN_KEYLOG=1`, переключает окно
сочетанием смены языка (из `HKCU\Keyboard Layout\Toggle`), убеждается, что раскладка окна русская,
и нажимает клавиши (только пока окно Postman на переднем плане). Приложение пишет `key <сочетание>
(<символ>) → <действие>` и `search "<текст>"`; то же — в строке состояния.

| Нажатие (раскладка 0419) | Результат |
|---|---|
| «о», «о», «л» в списке | `j (о) → Next`, `k (л) → Prev` |
| Ctrl+Q, Ctrl+U, Ctrl+2, Ctrl+Shift+Q, Ctrl+1, Ctrl+E, Esc, Insert | MarkRead, MarkUnread, ShowCalendar, NewMeeting, ShowMail, FocusSearch, ClearSearch, ToggleFlag |
| «о», «л» в поле поиска | текст `ол`, действий нет |

Раскладка 0409 — то же самое (`search "jk"`).

Найдена и исправлена ошибка, не связанная с раскладкой: j/k, стрелки, Home/End, PgUp/PgDn, Insert
были привязаны ко всему экрану и в поле поиска листали список вместо ввода текста. Теперь контекст
`Mailer && !Input`.

## S1-02. Простой и профиль листания

Стенд: Core Ultra 5 225H, Intel Graphics, 144 Гц, Windows 11. Профиль простоя — CPU и переключения
контекста по потокам (счётчики Windows), профиль листания — Very Sleepy 0.91 (выборка стеков, без прав
администратора) на сборке с номерами строк и без склейки одинаковых функций (`/OPT:NOICF`).

**Простой.** Будил кадр поток `VSyncProvider` Windows-платформы gpui: на каждом обновлении экрана
(158 раз в секунду) он инвалидировал все окна, главный поток просыпался ~200 раз в секунду.
Ядро gpui уже умеет кадры по запросу (`frame_waker`, `schedule_frame`), Windows-платформа их не
реализовывала. Патч (`docs/PATCHES.md`): окно просит кадр флагом, поток спит, пока запросов нет.

| | до | после |
|---|---|---|
| `idle_cpu_pct` (бенч) | 3,0 % | 0,0 % |
| пробуждения `VSyncProvider` | 158/с | 1–3/с |
| пробуждения главного потока | ~200/с | ~16/с (сообщения ОС, CPU 0,2 %) |

**Листание** (бенч: каждый кадр — прыжок на 25 строк и открытие письма). Гипотеза «рендер чаще, чем нужно»
не подтвердилась: один WM_PAINT — один кадр, кадр gpui ~5,2 мс, из них DirectX 0,12 мс. Время потока
интерфейса:

1. Наш код. Пометка «прочитано» — коммит redb с fsync в потоке интерфейса, до 30 мс на кадр
   (`ui_cpu_p99`). Вынесено в поток `cache-flags` с очередью: `ui_cpu_p99` 30 → 0,25 мс.
   Чтение страницы списка из redb (`Mailer::ensure` → `Cache::page`) — ~30 % времени потока, тоже в потоке
   интерфейса. Не исправлено: переносится с экраном списка (фаза 2).
2. gpui: шейпинг текста DirectWrite для новых строк (~25–30 %), раскладка taffy (~10–15 %), prepaint/paint.
   Каждый кадр бенча меняет почти весь текст, кэш строк не попадает.

Итог на этом стенде (3 прогона gpui, 2 — egui):

| | egui | gpui |
|---|---|---|
| `scroll_cpu_pct` | 58–64 | 92–102 |
| `scroll_ui_thread_cpu_pct` | 51–62 | 82–86 |
| `scroll_p50` / `scroll_p99`, мс | 6,9 / 10–36 | 7,0 / 10 (один прогон 36) |
| `rss_peak_mb` / `private_peak_mb` | 371–380 / 378 | 230 / 196 |
| `idle_cpu_pct` | 0,0–0,8 | 0,0 |
| `exe_mb` | 28,5 | 23,1 |

**Бенч.** Добавлены `exe_mb`, `private_peak_mb`, `idle_private_mb` (private bytes — «Выделенная память»
в диспетчере задач), `scroll_ui_thread_cpu_pct`; `POSTMAN_BENCH_SCROLL_FRAMES` удлиняет листание для профиля.
Оговорка: бенч помечает письма прочитанными в постоянном `demo.redb`, поэтому прогоны не одинаковы —
с каждым прогоном записей меньше. Исправить в S1-03 (отдельный ящик для бенча).

## S1-03. Листание: решение

Вопросы к решению (после реалистичного сценария — листание колесом/клавишами без открытия письма):
- чтение страниц списка вне потока интерфейса (предзагрузка окна строк);
- строки списка без flex-раскладки taffy и с кэшем шейпинга;
- сколько стоит кадр при 60 Гц — если реалистичный сценарий укладывается, ворота 0.3 пройдены.
