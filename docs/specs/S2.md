# S2. Фундамент (фаза 1 `docs/PLAN.md`)

Цель — до переноса экранов (фаза 2) заложить то, на чём они строятся: слои с проверкой, реестр команд,
правило «не падать», чек-лист соответствия Outlook, снимки экранов без человека и инфраструктуру базиса Pets
из Урфина. Задача = ветка `s2/NN-кратко` = один PR. Проверка — на Windows владельца.

## S2-01. Слои с проверкой

| Слой | Крейты | Правило |
|---|---|---|
| L0 | `ir` | без I/O |
| L1 | `jmap`, `cache`, `compose`, `calendar`, `search`, `worker` | без UI-зависимостей |
| L2 | `core` | без UI-зависимостей |
| L3 | `app-gpui`; `app` (egui, запасной) | только здесь gpui, egui, winit, rfd |
| вне | `demo` | данные для демо и тестов |

Приёмка:
- тест рабочей области по `cargo metadata`: у крейтов L0–L2 нет зависимостей (прямых и транзитивных,
  обычных — без dev) от `gpui*`, `egui*`, `eframe`, `winit`, `rfd`; слой ниже не зависит от слоя выше;
  новый крейт без слоя в таблице теста — ошибка;
- `core` не зависит от `rfd`: «Сохранить как…» и выбор файлов — в слое интерфейса, `core::files`
  принимает уже выбранный путь;
- clippy и тесты зелёные, поведение egui-версии не меняется (сохранение и прикрепление файлов работают).

## S2-02. Реестр команд

Команда: id (`mail.reply`, `mail.reply_all`, `mail.forward`, `mail.mark_read`, `mail.mark_unread`,
`mail.flag`, `mail.next`/`prev`/`first`/`last`/`page_down`/`page_up`, `view.mail`, `view.calendar`,
`calendar.new_meeting`, `search.focus`, `search.clear`…), название, хоткеи по умолчанию (Outlook), контекст
(список, поле ввода, окно письма), доступность. Описание команд — в `core` (без gpui), привязка к действиям
gpui и клавишам — в `app-gpui`. Приёмка: все нынешние хоткеи `app-gpui` идут из реестра; тест — каждый хоткей
Outlook из `docs/HANDOFF.md` §2a есть в реестре и привязан; `scripts/keys-ru.ps1` — без изменений результата.

## S2-03. «Не падать»

`clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` — `deny` в крейте, когда в нём не осталось
нарушений (сначала `core`, `cache`), остальные — `warn` со списком в этой спеке. На каждое исправленное место,
где падение возможно, — регрессионный тест. Фаззинг: случайные последовательности команд реестра над
демо-ящиком; инварианты — кэш читается, счётчики папок сходятся, процесс жив.

## S2-04. Чек-лист соответствия Outlook

`docs/PARITY.md` генерируется тестом из реестра (как `docs/COMMANDS.md` в Урфине): функция, хоткей, статус
(есть / частично / нет). Тест падает, если файл устарел или доля «есть» уменьшилась.

## S2-05. Снимки экранов без человека

Режим `postman-gpui --screens <каталог>`: демо-ящик, набор экранов (список, письмо, поиск, календарь,
помощник планирования) в PNG через PrintWindow; используется агентами для проверки интерфейса вместо
управления окном нажатиями.

## S2-06. Базис из Урфина

Переносим готовое: локализация EN+RU на Project Fluent с проверкой на сырые строки, тосты (справа сверху,
без перехвата фокуса, история командой), единственный экземпляр (mutex + named pipe), tracing с
дублированием ошибок и падений в журнал Windows «Приложение». Привязка к gpui — в L3, остальное — в `core`.

## Решения для владельца

| № | Вопрос | Рекомендация |
|---|---|---|
| 1 | Как переносить код из Урфина (S2-06): копией в Postman или общими крейтами `pets-*` в отдельном репозитории | Копией с пометкой источника; общие крейты — когда появится третье приложение |
