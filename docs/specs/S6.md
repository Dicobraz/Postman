# S6. Задачи и поручения (черновик)

Цель — модуль «Задачи» (Ctrl+4) и делегирование по утверждённому дизайну (`docs/DESIGN.md` → «Задачи»): списки,
быстрое добавление с разбором фразы, карточка задачи, письмо со сроком как задача, «Время в календаре», повтор;
поручения с приёмом, статусами, напоминанием и приёмкой результата, вкладки «Я поручил | Мне поручили», связь с
быстрым фильтром «Ждём».

Строим на S5: оболочка и рейл (S5-02), тема и тонированные кнопки (S5-01), хоткеи и KeyTips (S5-03), метки и сроки
на `keywords` (S5-04), быстрые фильтры (S5-06), Markdown → IR (S5-08), карточка приглашения (S5-12), свободные окна
(`calendar::find_slots`, S5-13), справочник (S5-14). Хранения задач на сервере пока нет: Stalwart v0.16.27 не
объявляет JMAP Tasks (`docs/STALWART.md` п. 2) — первой задачей проверяем, где задачи могут жить.
Задача = ветка `s6/NN-кратко` = один PR. Проверка — тесты, снимки `--screens` (обе темы), стенд для поведения
сервера; руками — владелец по `docs/MANUAL-TESTS.md`.

## Общие правила задач

- Как в S5: цвета — токены темы, тексты — Fluent (часть экрана `tasks.ftl`), действия — команды реестра `task.*`
  в обеих схемах клавиш, `parity` в том же PR; модальных окон нет, выполнение и удаление — тостом с «Отменить».
- Чужие данные — только в воркере: входящее поручение (.ics), VTODO, полученный по CalDAV, заметки из чужих задач.
  Новые входы воркера — в фаззинг.
- Демо-ящик (`demo`) получает задачи и поручения (все списки и статусы) — для снимков и `--bench`.
- Бюджеты `docs/HANDOFF.md` §2c не ухудшаются: `--bench` до и после в описании PR.

## S6-01. Стенд: хранение задач и поручение

Тест `tasks_storage_probe` в `crates/core/tests/stand.rs` (user1, user2; за собой убирает), находки — раздел
«Задачи» в `docs/STALWART.md`. Всё ниже — [проверить]:
- JMAP: `CalendarEvent/set` с JSCalendar `"@type": "Task"` (RFC 8984 §5.2) в календарь — создано или `notCreated`
  (какая ошибка); есть ли в `Calendar` признак компонентов (VTODO).
- CalDAV: адрес календаря пользователя (`/dav/cal/<аккаунт>/…`), `supported-calendar-component-set` содержит
  VTODO; `PUT` .ics с VTODO → `REPORT calendar-query` (comp-filter VTODO) находит; виден ли этот VTODO через JMAP
  (`CalendarEvent/query`) и в каком виде; `sync-collection` для изменений.
- Поручение: письмо user1 → user2 с iTIP `METHOD:REQUEST` + VTODO (ORGANIZER, ATTENDEE, DUE): доходит ли как
  письмо, кладёт ли сервер VTODO в календарь user2 сам (как VEVENT, п. 4); `METHOD:REPLY` с `PARTSTAT=ACCEPTED`
  обновляет ли копию у user1.
- Запасной путь: FileNode (`filenode` есть) — создать файл, прочитать, изменить, `FileNode/changes` у второго клиента.
- Напоминания: шлёт ли сервер `alerts` событий/задач сам (письмом) — для решения 7.

Приёмка: тест стенда; раздел в `docs/STALWART.md`; путь хранения и формат поручения — строкой в `S0-decisions.md`
решением владельца (решения 1, 2).

## S6-02. Модель задач, хранилище, кэш

- Тип `Task` в `calendar` (L1, рядом с `Event`; JSCalendar Task: `title`, `due`, `start`, `progress`, `priority`,
  `recurrenceRules`, `alerts`, `relatedTo`, `participants`) ↔ VTODO; поля Postman (проект, «Когда-нибудь», ссылка на
  письмо, порядок подзадач) — свойства с префиксом `postman` / `X-POSTMAN-` (решение 2). Без I/O.
- `core::tasks` (L2): списки (Входящие — без срока и проекта; Сегодня — просроченные сверху; Предстоящие; Из почты;
  Когда-нибудь; Выполненные), проекты с прогрессом (выполнено / всего), категории — та же модель, что у почты (S5-04).
- Хранилище — трейт `TaskStore` с реализацией по итогу S6-01: JMAP | CalDAV (модуль `jmap::caldav` или крейт
  `caldav` L1 — сначала в таблицу `layers.rs`; разбор .ics — в воркере) | FileNode | локально (redb, экспорт/импорт).
- Кэш: таблица задач в `cache` (миграция схемы), изменения — в потоке синхронизации (`*/changes` или
  `sync-collection`), офлайн-правки — очередь, как у почты.

Приёмка: тесты модели (VTODO ↔ `Task` туда-обратно на корпусе: Thunderbird, Apple, Outlook-экспорт), отбора по
спискам и прогресса проекта, миграции кэша; тест стенда `task_round_trip` (создать → у второго клиента через
изменения → выполнить → удалить).

## S6-03. Письмо ↔ задача

- Письмо со «Сроком» (`$pm_due_YYYYMMDD` + `$flagged`, S5-04) — задача списка «Из почты»: представление над кэшем
  писем, без копии. Запись в хранилище появляется, только когда у такой задачи правят что-то кроме срока
  (заметки, подзадачи, проект), со ссылкой на письмо (`Message-ID` + `emailId`) — решение 4.
- Выполнение задачи снимает срок у письма (`keywords` долой — одним `Email/set`); смена срока в задаче меняет его
  у письма и наоборот; снятие срока в почте закрывает задачу (решение 4).
- Из карточки задачи — «Открыть письмо» (письмо во вкладке, папка не меняется); у письма — метка срока, как в S5-05.

Приёмка: тесты связи (срок туда-обратно, выполнение → `keywords`, письмо удалено → задача без ссылки, не падает);
тест стенда `mail_due_is_task` (срок у user1 → задача; выполнить → `keywords` сняты у второго клиента).

## S6-04. Быстрое добавление

- Разбор фразы — функция без I/O в `core::tasks::parse` (ru и en по языку интерфейса): дата («сегодня», «завтра»,
  «послезавтра», «в пт», «через 3 дня», «на следующей неделе», «15.11», «15 ноября»), время («в 15», «в 15:30»,
  «утром» / «вечером» — часы из настроек календаря), `#категория` (по названию с допуском регистра и раскладки),
  «!» — приоритет. Остаток — название. Неоднозначность — ближайшая дата впереди (решение 5).
- Поле одной строкой над списком; распознанное — чипами в самом поле (× снимает распознавание, текст возвращается);
  Enter — добавить в текущий список (в «Сегодня» без даты — срок сегодня), Esc — очистить.

Приёмка: таблица случаев разбора (≥ 60 строк: формы дат, время, конец месяца/года, неверная раскладка в `#`,
«!» в середине, без даты); снимок `task-quickadd` (чипы).

## S6-05. Модуль «Задачи»

- Рейл: кнопка «Задачи», Ctrl+4 (`view.tasks`); слева — списки, проекты с прогрессом, категории в цветах почты,
  пункт «Поручения» (S6-11); справа — карточка задачи (S6-06), как панель чтения.
- Строка задачи: круг выполнения, название, срок (те же стили, что в почте: янтарный текст / плотная заливка —
  функция S5-05), категория, значок письма, «!» — акцентом (другого приоритета нет), счётчик подзадач.
- Выполнение: зачёркивание и уход в «Выполненные» через 2 с, тост «Отменить»; перетаскивание — порядок и перенос в
  список/проект.
- Команды (решение 6): Ctrl+N — новая задача (в модуле), Space — выполнено/вернуть, Insert — срок (как в почте), Del — удалить, F2 —
  переименовать, Enter — открыть письмо задачи, стрелки — по списку; KeyTips — над кнопками модуля.

Приёмка: тест модели выполнения (таймер 2 с, отмена); снимки `tasks`, `tasks-today` (просроченные сверху),
`tasks-project`, `tasks-done` в обеих темах; `--bench` с 5 000 задач в демо.

## S6-06. Карточка задачи

- Поля: название, срок, напоминание, проект, категория, ссылка на письмо, «Время в календаре» (S6-08), повтор
  (S6-07), «Поручить» (S6-10). Правка на месте, сохранение сразу, «Отменить» — тостом.
- Подзадачи: список с кругами выполнения, Enter — следующая, перетаскивание — порядок; прогресс в строке задачи.
- Заметки — Markdown с живым отображением (компонент композера S5-08, рендер через IR).

Приёмка: тесты модели подзадач (порядок, прогресс, выполнение всех ≠ выполнение задачи); снимки `task-card`,
`task-card-mail` (из письма), `task-notes`.

## S6-07. Повтор и напоминания

- Повтор (решение 8): каждый день, по будням, по неделе (дни), по месяцу (число), по году; «от срока» или «после
  выполнения через N»; хранение — `recurrenceRules` / RRULE. Выполнение повторяющейся — следующая копия со сдвигом.
- Напоминание: время из карточки, по умолчанию — из настроек; срабатывает тостом `pets-ui` и уведомлением Windows,
  если окно свёрнуто (решение 7); «Отложить на 10 мин / 1 ч / завтра» — в тосте.

Приёмка: таблица случаев повтора (31-е число, 29 февраля, смена часового пояса, «после выполнения»); тест
планировщика напоминаний (модель, часы подменяются); снимок `task-repeat`.

## S6-08. «Время в календаре»

- Кнопка в карточке: блок длительностью из задачи (по умолчанию — настройка календаря, S5-10) в ближайшее свободное
  окно своего календаря (`calendar::find_slots` по своей занятости и рабочим часам); ←/→ — соседние окна, Enter —
  поставить. Блок — событие «занят» со ссылкой на задачу (`relatedTo`), без участников.
- Выполнение задачи — блок остаётся (было); удаление задачи — строка «Удалить и блок?» в карточке. Перенос блока в
  календаре меняет «запланировано» у задачи.

Приёмка: тест выбора окна (модель: рабочие часы, «вне офиса», граница дня); снимки `task-timeblock`,
`calendar-taskblock`; тест стенда `task_block_in_calendar`.

## S6-09. Поручения в `core`

- Формат (решение 2): iTIP по RFC 5546 для VTODO — `METHOD:REQUEST` (поручить, изменить срок, вернуть с
  комментарием), `REPLY` (`PARTSTAT`: ACCEPTED, DECLINED, IN-PROCESS, COMPLETED — «готово, на проверку»),
  `COUNTER` (предложить срок), `CANCEL` (забрать); приёмка результата — `STATUS:COMPLETED` у поручившего и REPLY-итог
  исполнителю. Наблюдатели — `ATTENDEE;ROLE=NON-PARTICIPANT`, получают только итоги (решение 9). Письмо — `text/plain` +
  `text/html` для людей без Postman + `text/calendar` (как `calendar::imip_reply`).
- Приём: письмо с VTODO разбирает воркер; `core` сопоставляет по `UID` и `SEQUENCE`, ведёт ленту шагов (кто, что,
  когда, комментарий); устаревшие (`SEQUENCE` меньше) — игнор с записью в журнал.
- «Напомнить» — повтор REQUEST без изменения `SEQUENCE` с пометкой в теле; не чаще раза в сутки (решение 10).
- Задача остаётся у поручившего до приёмки; у исполнителя — своя копия в «Мне поручили».

Приёмка: тесты автомата статусов (таблица переходов, недопустимые — ошибка), генерации/разбора iTIP на корпусе
(Thunderbird, Outlook-экспорт); фаззинг нового входа воркера; тест стенда `delegation_round_trip` (user1 → user2:
принять → в работе → готово → принять результат; user3 — наблюдатель, получил итог).

## S6-10. Поручение на экране

- «Поручить» в карточке: исполнитель из справочника (поиск S5-14, неверная раскладка), наблюдатели по желанию,
  срок, комментарий; отправка — Ctrl+Enter.
- У исполнителя — карточка как приглашение (раскладка S5-12): детали сверху, в строку «Принять» (заливка) /
  «Предложить срок» / «Отклонить» (тонированные); дальше «В работе» → «Готово — на проверку». Та же карточка — над
  телом письма-поручения.
- У поручившего — лента шагов, «Напомнить», «Принять результат» (заливка) / «Вернуть с комментарием», «Изменить
  срок», «Забрать» (строка подтверждения).
- Статусы — круги 20 px: ждёт — серый точечный, принял — синий ✓, в работе — синий ▶, готово — зелёный ✓✓,
  отклонил — тёмно-серый ✕; предложенный срок — янтарной датой.

Приёмка: снимки `delegate` (форма), `delegation-in` (у исполнителя), `delegation-mail` (карточка в письме),
`delegation-steps` (у поручившего), `delegation-statuses` в обеих темах.

## S6-11. Раздел «Поручения» и «Ждём»

- Слева один пункт «Поручения»; над списком вкладки «Я поручил» | «Мне поручили»; на «Я поручил» флажок «Только
  свои» (по умолчанию стоит; снят — ещё и где я наблюдатель). Строка — исполнитель (или поручивший), статус-круг,
  срок, последний шаг.
- Быстрый фильтр «Ждём» (S5-06, решение S5 4) дополняется: письма-поручения по моим невыполненным поручениям
  (из «Отправленных», по `UID`); счётчик учитывает их без дублей с «Ждём ответа».

Приёмка: тест отбора вкладок и «Только свои»; тест «Ждём» на демо-ящике (поручение без приёмки — в фильтре, после
приёмки — нет); снимки `delegations-out`, `delegations-in`, `quickfilters` (с поручениями).
