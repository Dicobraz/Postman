# S5. Новый дизайн в gpui (черновик)

Цель — перевести интерфейс `app-gpui` на утверждённый дизайн (`docs/DESIGN.md`, пересмотр ADR 0002): оболочка с
вкладками и командной строкой, тема и плотность, метки и сроки на `keywords`, фильтры, беседа лентой,
Markdown-композер во вкладке, вложения со встроенным просмотром, две схемы хоткеев и KeyTips, настройки, правила (Sieve),
календарь, карточка приглашения, встреча и контакты по макетам. Решения владельца 2026-10-20 (`S0-decisions.md`) — основание.

Строим на том, что есть: части экрана (`list`, `folders`, `reading`, `bar`, `mailer`), реестр команд
(`commands.rs`, `pets-commands`), тосты и история (`pets-ui`), модели окна письма и встречи (`compose.rs`, `meeting.rs`
— модели без gpui остаются, меняется view), адресная книга с неверной раскладкой (`postman_core::contacts`).
Задача = ветка `s5/NN-кратко` = один PR. Проверка — тесты, снимки `--screens` (обе темы), стенд для нового
поведения сервера; руками — владелец по `docs/MANUAL-TESTS.md`.

## Общие правила задач

- Цвета, отступы, высоты строк — только токены темы (`theme.rs`); литерал `rgb(0x…)` вне него ловит тест
  `no_raw_colors` (как `no_raw_ui_strings`). Сейчас литералов ~110 — убирает S5-01.
- Тексты — Fluent, оба языка; действия — команды реестра (обе схемы клавиш, после S5-03), `parity` в том же PR.
- Снимки: каждая задача добавляет свои сцены в `screens.rs` и проверяет их в светлой и тёмной теме
  (`--screens <каталог> --theme dark`). Окна письма и встречи становятся вкладками — их сцены снимаются в главном окне.
- Бюджеты `docs/HANDOFF.md` §2c не ухудшаются: `--bench` до и после в описании PR (листание, простой, память, старт).
- Чужие данные (цитаты, PDF, архивы, макросы) — только в воркере-песочнице; новые входы воркера — в фаззинг.
- Модальных окон нет: подтверждения — строкой, уведомления — тостами (с «Отменить», где действие обратимо).

## S5-01. Тема и плотность

- `app-gpui/src/theme.rs`: токены (фон, поверхности, текст основной/вторичный, акцент, граница, выделение,
  наведение, безопасность, срок, категории, свободное время); светлая и тёмная таблицы из `DESIGN.md` → «Цвет»:
  точки и полосы OKLCH L 0,62 C 0,14, подложки меток L 0,95, текст метки L 0,42; тёмная — основной #D2D2D2, вторичный #A6A6A6,
  акцент #0067C0 / #7DB8E8 (#8CC4F0 — наведение). Перевод OKLCH → sRGB — функция с тестом, не таблица руками.
- Тест палитры: в одном списке (категории; цвета календарей; красный безопасности; янтарный сроков) ΔE2000 ≥ 25
  попарно в обеих темах; контраст текста метки на подложке ≥ 4,5:1. Тот же контроль — функция для палитры
  в «Настройки → Категории» (S5-10).
- Кнопки — два вида токенов: главное действие — заливка акцентом; второстепенные — тонированные, без рамки
  (подложка #EBF3FC, текст #0F548C; тёмная #23364F / #BFDDFF). Тест: в обеих темах фон кнопки ≠ фон любой
  поверхности, на которой она лежит; контраст текста ≥ 4,5:1.
- Свободное время (S5-13): по умолчанию розовый бренда #E4107F, варианты — зелёный, синий, бирюзовый; рамка,
  свечение (наведение, выбор) — токены от выбранного цвета; «вне офиса» — серый; внешние — прозрачный сине-стальной.
- Тема: «Как в системе» (по умолчанию, `AppsUseLightTheme`, смена на лету) | светлая | тёмная; `--theme light|dark`.
- Плотность: обычная | компактная (без аватара и превью, строка списка ниже); высоты — токены, кэшируемые view
  получают размер из темы.
- Все `rgb(0x…)` в `app-gpui/src` → токены, поведение не меняется.

Приёмка: тесты палитры, кнопок и `no_raw_colors`; снимки `buttons` (главная и тонированные на всех поверхностях),
`list`, `letter`, `calendar`, `compose` в обеих темах и обеих плотностях; `--bench` без ухудшения.

## S5-02. Оболочка

- Заголовок окна — только вкладки (своя полоса заголовка gpui: перетаскивание, кнопки окна, двойной щелчок,
  Snap Layouts) [проверить на патче `pets-gpui-windows`]. Первая вкладка — модуль (закреплена), остальные — документы:
  новое письмо, письмо, настройки, встреча. Ctrl+T / Ctrl+W, Ctrl+Tab — по вкладкам; состояние вкладки — своя view.
- Рейл модулей слева: Почта, Календарь, Контакты (Задачи — S6); Ctrl+1…3 (`view.*`, Ctrl+4 — S6); `Section` в
  `mailer.rs` → модуль рейла.
- Командная строка вместо `bar.rs`: одна строка, одна акцентная кнопка «Новое письмо», команды по контексту
  модуля и выделения (те же команды реестра); поиск справа (Ctrl+E): «Везде | Текущая папка», результаты по папкам
  (группы — S5-05), подсветка совпадений янтарным, чипы «Уточнить» (от, есть вложения, период).
- Строка состояния: синхронизация, квота (S4-05), 🔔 история — панель справа; офлайн — строка состояния, метка у
  аккаунта, тонкий баннер над списком. Тосты: стопка ≤ 3 + «+N», предупреждения нейтральные, красный — только
  ошибки (`pets-ui`, правка — там).
- ADR 0002: отметка «пересмотрен — `docs/DESIGN.md`» (окна письма и встречи → вкладки).

Приёмка: снимки `list` (рейл, вкладки, командная строка), `search` (группы, подсветка), `offline`; тест модели
вкладок (открыть, закрыть, порядок, закрытие грязной вкладки — строка подтверждения); `scripts/resize-check.ps1` —
без регресса ресайза и разворачивания.

## S5-03. Хоткеи: две схемы, KeyTips, палитра

- `pets-commands`: у команды клавиши по схемам — `Outlook` (по умолчанию) и `Single` (одиночные, как Gmail:
  R, A, F, E, C, Q/U, `/`; A/T/N — только на карточке приглашения в фокусе). Правка в `pets`, затем поднять `rev`.
- Одно правило (`DESIGN.md` → «Хоткеи»): не больше одного модификатора; Ctrl + буква или цифра — команды; без
  модификатора — навигация и действие над выделенным (стрелки, Enter, Esc, Del, Insert, F2, F3, Home, PgUp/PgDn,
  Backspace); Alt не используется. Исключения схемы Outlook ради привычки — Ctrl+Shift+R/Q/C/B/V, Shift+F3.
- Реестр приводится к таблице хоткеев (`DESIGN.md` → «Хоткеи»): убрать `j`/`k` из Outlook (→ `Single`), `alt-s`,
  `alt-up`/`alt-down`; Insert — «Срок» (`mail.due`, S5-04), Backspace — архив (`mail.archive`), Ctrl+Shift+V —
  переместить, календарь: Home, PgUp/PgDn, 1…4 (контекст сетки), встреча: Ctrl+Enter, Ctrl+D, Ctrl+Shift+B, ←/→ + Enter.
- Тест схемы: в `Outlook` не больше одного модификатора, кроме Ctrl+Shift+R/Q/C/B/V и Shift+F3; Alt нет нигде;
  в `Single` одиночные клавиши — только вне полей ввода; конфликтов внутри схемы нет; русская раскладка — как в S1-01.
- KeyTips: удержание Ctrl 0,4 с без другой клавиши — плашки с клавишами над всеми видимыми кнопками (командная
  строка, рейл, вкладки, карточки, формы) по текущей схеме; отпустил или нажал клавишу — пропали. Подсказка при наведении «Название (клавиша)»; в тексте кнопок клавиш нет.
- Палитра Ctrl+K: оверлей под командной строкой; группы Команды / Папки / Быстрые фильтры / Письма; поиск с неверной
  раскладкой (как адресная книга).
- Схема выбирается в «Настройки → Клавиатура» (S5-10): «Outlook» по умолчанию, «Одиночные клавиши» выключена.
- `docs/PARITY.md`: столбец схемы `Single`.

Приёмка: тест схемы, `parity`, тест таймера KeyTips (модель без gpui); снимки `keytips` (обе схемы), `palette`;
`scripts/keys-ru.ps1` — новые клавиши.

## S5-04. Метки и сроки на `keywords`

- Кэш: `EmailRow` + `keywords` (без `$seen`/`$flagged`, они — поля) и «Кому мне» (для фильтра «Мне»); миграция
  схемы redb; синхронизация `keywords` уже читает (`jmap/mail.rs`) — дописать в кэш и `Email/changes`.
- Модель категорий в `core`: ключевое слово (ASCII, решение 3) → название, цвет из палитры S5-01, порядок; срок —
  ключевое слово с датой (`$pm_due_YYYYMMDD`) вместе с `$flagged`; «Ждём ответа», «Напомнит», «Исчезнет» — свои
  ключевые слова. Где хранить таблицу категорий — решение 3.
- Команды: назначить/снять категорию, `mail.due` (Insert: срок «сегодня», выбор даты — строкой), снять срок.
- Стенд [проверить]: `Email/set keywords/<kw>` → у второго клиента через `Email/changes`; какие символы сервер
  принимает в ключевом слове (не-ASCII, `/`); видимость в IMAP (флаги) — запись в `docs/STALWART.md`.

Приёмка: тесты кэша (миграция, запись/чтение меток), модели категорий и разбора срока; тест стенда
`keywords_round_trip`.

## S5-05. Список

- Строка (`list.rs::list_row`): слева цветная полоса категории; метки в строке отправителя справа — категория первой,
  имя сокращается до ≥ 60 px, метки обрезаются слева; регистр — только первое слово с заглавной.
- Сроки: впереди — янтарный текст с часами без подложки («До чт»); прошёл — плотная янтарная заливка
  («Просрочено 1 д»); «Ждём ответа», «Напомнит», «Исчезнет», «Внешний» — нейтральные серые. Текст срока — функция с тестом.
- «Все папки» и поиск: результаты группами по папкам, группы по датам; группы сворачиваются (виртуальный список
  со строками-заголовками, позиция прокрутки — как сейчас `Positions`).
- Выделение: чекбоксы на месте аватаров (Ctrl+A), панель массовых действий вместо заголовка списка, сводка в панели
  чтения; контекстное меню с подменю категорий. Del, Backspace (архив), Ctrl+Shift+V (переместить — оверлей папок) —
  тостом с «Отменить».
- «Сообщить о фишинге»: красная маска (#CD605A); действие — решение 6.

Приёмка: тесты текста срока, обрезки меток (модель ширин), группировки; снимки `list` (метки, сроки обоих стилей),
`allfolders`, `bulk`; `--bench` листания без ухудшения.

## S5-06. Фильтры

- Модель фильтра в `core` (без gpui): панель — группы Состояние (непрочитанные, упоминания, вложения, флаг),
  Отправитель (внешние), Категория; область — «Входящие | Все папки»; быстрые фильтры — Угрозы → Срок → Ждём → Мне →
  Истекают (определения — решение 4). Логика: закладки между собой ИЛИ, с панелью И; внутри группы панели ИЛИ,
  между группами И. Исполнение — по кэшу (`PageSource`), счётчики в фоне.
- Боковая панель: воронка у «Входящих» — Папки ↔ Фильтры, счётчик — только фильтры панели; в режиме фильтров —
  карточка, вверху «Где искать». Над списком одна строка: папка или «Все папки», чип фильтров панели (×), «N из M»,
  сортировка.
- Быстрые фильтры — закладки поверх нижнего края карточки списка, растут снизу вверх; равная ширина, стабильные
  позиции, нули бледнеют, включённая — белая с цветной полосой; «×» скрывает (вернуть: Вид → Быстрые фильтры);
  по наведению — всплывающая панель поверх списка без сдвига.

Приёмка: тест логики ИЛИ/И (таблица случаев) и счётчиков на демо-ящике; снимки `filters`, `quickfilters`,
`quickfilters-hover`.

## S5-07. Беседа

- Лента беседы в панели чтения (по умолчанию): письма беседы из всех папок (`Thread/get`, `thread_id` в кэше),
  только новый текст каждого письма, разделители по дням, свои письма справа на светлой подложке; цитаты —
  переключателем.
- Цитаты отделяет воркер: разметка в IR (`blockquote`, `gmail_quote`, `divRplyFwdMsg`, «-----Original Message-----»,
  строки `>`); UI только прячет помеченное. Корпус писем популярных клиентов — в тесты `ir`.
- Настройки → Чтение: «Стопка в панели чтения» и «В списке, как Outlook»; вид для папки — ПКМ по папке.
  Ctrl+→ / Ctrl+← — по письмам беседы.

Приёмка: тесты отделения цитат на корпусе; фаззинг нового входа воркера; снимки `thread`, `thread-quotes`, `stack`.

## S5-08. Новое письмо и ответ

- Окно письма → вкладка: `compose.rs::Model` (поля, автосохранение, закрытие) без изменений, view — во вкладке;
  закрытие грязной вкладки — строка. Ответ — в панели чтения под лентой, «Открыть во вкладке».
- Markdown-композер: ввод Markdown с живым отображением (своя разметка — не чужие данные, разбор в `compose`, L1);
  кнопки панели форматирования вставляют разметку, Ctrl+B/I/U; отправка — text/plain + text/html через IR (`§3a`).
- Цвета: подписи полей и кнопки панели — акцент, единый с «Отправить». Проверки перед отправкой (пустая тема,
  «вложение» в тексте без вложения, внешние адресаты); DLP-подсказка (номер карты, Луна) — тёмно-красная подложка.

Приёмка: тесты Markdown → IR → html/plain (таблица случаев), проверок перед отправкой, DLP; снимки `compose`,
`reply` (в панели чтения), `compose-checks`; тест стенда отправки — без изменений, зелёный.

## S5-09. Вложения

- Лента сразу под шапкой письма; карточка в одну строку 40 px, статус иконкой (загрузка, готово, ошибка, опасно).
- Встроенный просмотр без внешних программ: картинка (есть), архив (список файлов), PDF (движок — решение 5); разбор
  в воркере, в UI — пиксели и списки; пока открыт просмотр, текст письма скрыт; Esc — назад.
- Макросы: определение в воркере (OOXML с `vbaProject.bin`, `.docm/.xlsm/.pptm`, OLE с потоками VBA); красный
  щиток и тонкая красная полоса, «Открыть» заблокировано, подробности — карточка безопасности (решение 7).

Приёмка: тесты определения макросов на образцах (и на переименованных файлах); фаззинг входов воркера (PDF, zip);
снимки `attachments`, `preview-pdf`, `preview-zip`, `macro`.

## S5-10. Настройки

- Вкладка; слева навигация по разделам с поиском (по названиям и подписям настроек). Хранение — файл настроек в
  `data_dir()` (без секретов), применение на лету.
- Разделы: Категории (таблица, правка на месте, палитра с запретом близких цветов — проверка S5-01); Быстрые фильтры,
  сроки и жизненный цикл; Аккаунты (добавление в 3 шага на месте — заменяет `signin.rs`; пароль — Диспетчер учётных
  данных или не хранится; TLS ≥ 1.2, проверка отзыва [проверить]; автоответ S4-05); Чтение (вид беседы, панель
  чтения справа/снизу/скрыта, внешние картинки не грузятся, предупреждение о несовпадении текста и адреса ссылки);
  «Боковая панель справа» для карточки приглашения (S5-12); Подписи и шаблоны; Клавиатура (схема S5-03, таблица
  из реестра); Правила (S5-11).
- Календарь: рабочая неделя и часы, вид по умолчанию, шаг сетки, часовой пояс и второй пояс; длительность и
  напоминание по умолчанию, «Начинать на 5 мин позже»; цвет свободного времени (розовый бренда | зелёный | синий |
  бирюзовый, образец рамки рядом); цвета календарей коллег по владельцу (палитра S5-01, решение 8), имя владельца в
  событиях; приглашения — добавлять «под вопросом», удалять письмо после ответа. Читают S5-12, S5-13, `core::invite`.
- Первый запуск — добавление аккаунта на месте (`--screens --live` без окружения → сцена `signin` = шаг 1).

Приёмка: тест чтения/записи файла настроек и поиска по разделам; снимки `settings-*` по разделам (в т. ч.
`settings-reading`, `settings-calendar`), `signin`.

## S5-11. Правила почты (Sieve)

- `core`: модель правила (условие: от, кому, тема, содержит; действие: в папку, категория, пометить, удалить,
  переслать) ↔ скрипт Sieve (`fileinto`, `imap4flags` для категорий, `redirect`); свой скрипт `postman` с маркерами,
  разбор только своего — чужой показывается текстом и при сохранении не ломается.
- JMAP Sieve: `SieveScript/get|set`, `SieveScript/validate`, активный скрипт; включить/выключить правило.
- Редактор — раздел «Настройки → Правила»: список, правка условия и действия на месте.
- Стенд [проверить]: capability `urn:ietf:params:jmap:sieve` и методы; «тема содержит X → папка Y» и «→ категория»
  срабатывают на новом письме; находки — `docs/STALWART.md`.

Приёмка: тесты генерации/разбора (обход туда-обратно), чужой скрипт не меняется; тест стенда `sieve_rule_applies`;
снимок `settings-rules`.

## S5-12. Календарь

- Неделя по макету: переключатель видов над сеткой (правый край по сетке), поиск над панелью события; ответ на
  приглашение — полоса во всю ширину панели. Home, PgUp/PgDn, 1…4 (день/раб. неделя/неделя/месяц — месяц, если в
  макете есть; иначе 1…3).
- Цвет события — цвет календаря владельца (свой, отдела, каждого коллеги; палитра S5-01, решение 8); у событий
  коллег — имя владельца; без ответа — пунктир; выбранное — свечение по контуру.
- Статусы участников — заливные кружки со значком: принял — зелёный ✓, под вопросом — синий ?, отклонил — серый ✕,
  нет ответа — серая точечная заливка; легенда-счётчик над списком.
- Приглашение в письме (`invite_card.rs`): карточка над телом — сверху детали (дата, время, место, организатор,
  «N из M приняли»); под ними вертикальный календарь дня на всю ширину (свои события серые, приглашение синее,
  пересечение фиолетовое, подписи видны); ниже в строку «Принять» (заливка) / «Под вопросом» / «Отклонить»
  (тонированные). Опция «Боковая панель справа» (S5-10, Чтение): кнопки столбиком и лента дня в колонке 300 px.
  Состояния: без ответа, «Вы приняли», «Отменена». Раскладка дня — `calendar::layout_day`.

Приёмка: снимки `calendar`, `event`, `invite`, `invite-side`, `invite-accepted`, `invite-cancelled` в обеих темах;
тест назначения цветов владельцам; тест цвета пересечения (свои ∩ приглашение) в модели ленты дня.

## S5-13. Встреча

- Окно встречи → вкладка, одна форма: поля сверху, сетка занятости ниже (модель `meeting.rs::MeetingModel` и
  `find_slots` — без изменений). Добавленный участник сразу в сетке; Ctrl+Shift+B — добавить участника.
- «Только общее свободное время» подсвечивает окна, где свободны все; клик ставит встречу; ←/→ по свободным окнам,
  Enter — выбрать (title у сетки, без подписи под ней).
- Свободные окна — тонкая мягкая рамка цвета свободного времени (S5-01; по умолчанию #E4107F, выбор — S5-10),
  свечение при наведении и выборе; «вне офиса» — серый; внешние и неизвестная занятость — прозрачный
  сине-стальной, без штриховки.
- «Помощник планирования» как отдельная кнопка уходит; в календаре — «Подобрать время» (открывает встречу, без хоткея).

Приёмка: тест навигации по окнам ←/→ (модель); снимки `meeting`, `meeting-common`, `meeting-slot` (выбранное окно,
свечение), `meeting-green` (другой цвет свободного времени); тест стенда `calendar_through_sync` —
зелёный.

## S5-14. Контакты

- Модуль (Ctrl+3): справочник (Principals, только чтение), мои контакты (ContactCard), «Часто пишу» (адресная книга:
  частота и давность); поиск — `AddressBook` (неверная раскладка, транслит).
- Карточка: имя, адреса, телефоны, организация, занятость на сегодня (`Principal/getAvailability`); «Написать»
  (Ctrl+N), «Встреча» (Ctrl+Shift+Q), «Вся переписка». Свой контакт: Ctrl+Shift+C, F2, Ctrl+S, удаление — строкой.
- Данные и `ContactCard/set` — S4-02 (решение 1); здесь — экран.

Приёмка: тест поиска в неверной раскладке по контактам и справочнику; снимки `contacts`, `contact-card`;
тест стенда S4-02 — зелёный.
