# S4. Сервер и стабилизация (фаза 3 `docs/PLAN.md`)

Цель — от рабочего клиента (фаза 2) к внутреннему использованию: одно приложение на gpui без egui, сборка и
установка под Windows, контакты и справочник, устойчивость на реальных ящиках, инструкция пользователя.
Задача = ветка `s4/NN-кратко` = один PR. Проверка — тесты, стенд Stalwart (`docs/STALWART.md`), снимки
`--screens`; руками — владелец по `docs/MANUAL-TESTS.md`. Агенты не управляют окнами нажатиями (только снимки).

### Как получить сертификат подписи (к решению 1)

Приложение внутреннее, поэтому основной путь — внутренний: служба сертификатов AD (AD CS) выпускает сертификат по
шаблону «Подписывание кода», корневой сертификат и издатель раздаются групповой политикой («Доверенные издатели»);
подписанный exe тогда доверен на всех машинах домена, политики AppLocker/WDAC могут разрешать его по издателю.
Внешний сертификат (OV от публичного CA, ключ — только на аппаратном токене или облачном HSM) нужен, если exe
скачивают из Интернета (SmartScreen); часть западных CA не продаёт сертификаты российским организациям [проверить
у выбранного CA]. Для CI: PFX в секрете `WINDOWS_CERT_PFX_BASE64` (внутренний) или облачная подпись поставщика.

## S4-01. Сборка Windows

- egui-версия `app` удалена (gpui её догнал, `docs/PLAN.md` фаза 2); слои, CI, документы — без неё.
- Исполняемый файл — `postman.exe` (бинарь пакета `postman-gpui`); в release без консоли (`windows_subsystem`),
  для `--bench`/`--screens` вывод в консоль родителя (агенты читают строки `screen …`, `bench …`).
- Ресурсы exe: значок, версия, манифест (DPI per-monitor v2, длинные пути, UTF-8).
- Архив `Postman-<версия>-windows-x64.zip` в CI: `postman.exe`, `postman-worker.exe`, `README.txt`, `install.ps1`.
- `install.ps1` (без прав администратора): копия в `%LOCALAPPDATA%\Programs\Postman`, право AppContainer на каталог
  (иначе песочница воркера не стартует вне Program Files), ярлык в «Пуск»; `-Uninstall`. Источник журнала Windows —
  отдельный шаг с правами администратора (по желанию).
- Подпись: `signtool` в CI, если задан секрет сертификата (решение 1).

## S4-02. Контакты и справочник

- Раздел «Контакты» (Ctrl+3, `view.contacts`): личные контакты (JMAP ContactCard) и сотрудники (Principals),
  поиск, карточка (имя, адреса, телефоны, организация), «Написать письмо».
- Создать, изменить, удалить личный контакт (`ContactCard/set`); подтверждение удаления — строкой.
- Сотрудники (Principals) — в подсказках адресов окна письма и окна встречи (`AddressBook::add_directory`).
- Демо — контакты из демо-ящика; живой ящик — через синхронизацию; тест стенда на создание и правку карточки.

## S4-03. Стабилизация живого ящика

- Догрузка писем при прокрутке (`Command::LoadMore`), счётчики папок верны.
- Отказ сервера в доступе (401) при сохранённом входе — снова строка входа, пароль из диспетчера — заменить.
- Тексты синхронизации — через Fluent: `postman_core::sync` отдаёт коды и данные (не готовые русские строки).
- Неделя календаря обновляется по push.
- Большой ящик: сценарий заполнения ящика стенда (20–50 тыс. писем, `Email/import`), замеры на живом ящике —
  первая синхронизация, память, CPU в простое и при листании; бюджеты `docs/HANDOFF.md` §2c.

## S4-04. Инструкция пользователя

`docs/USER-GUIDE.md`: установка, вход, почта, календарь и занятость, контакты, клавиши — таблица из реестра
команд (генерируется тестом, как `docs/PARITY.md`).

## Вне стенда (остаётся [проверить])

- Вход через внешний OIDC (`docs/IDENTITY.md`) — на стенде только пароли.
- iMIP с внешними доменами — у стенда нет внешнего домена.

## S4-05. Автоответ и квота

- «Автоматические ответы» (как в Outlook): вкл/выкл, период, тема, текст — `VacationResponse/get|set`; пока включён —
  полоса в окне «Автоответ включён… Выключить».
- Заполненность ящика (`Quota/get`) — в строке состояния, предупреждение тостом при > 90 %.
- Тест стенда: включить, проверить автоответ письмом от другого пользователя, выключить.

## S4-06. Общие ящики

- Аккаунты из `session.accounts`, кроме основного (`mail:share`, `isPersonal: false`), — отдельными ветками дерева
  папок; синхронизация по каждому аккаунту, кэш — по аккаунту.
- Отправка от имени общего ящика — Identity этого аккаунта, если сервер позволяет.
- На стенде — общий ящик (группа или делегирование через `x:Account/set`, см. README стенда) и тест.

## S4-07. Правила (Sieve)

- Список правил (`SieveScript/get`, активный скрипт), простой редактор: условие (от, тема, кому содержит) →
  действие (переместить в папку, пометить, удалить, переслать); генерация скрипта Sieve на клиенте, проверка сервером
  (`SieveScript/validate`), включить/выключить.
- Скрипт, написанный не нашим редактором, — показать текстом, не ломать при сохранении.
- Тест стенда: правило «тема содержит X → папка Y» срабатывает на новом письме.
