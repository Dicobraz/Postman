# S7. Exchange (on-prem) и IMAP/SMTP

Решение владельца 2026-10-23 (`S0-decisions.md`): на переходный период Postman работает и с Exchange компании —
свой сервер Exchange 2016/2019/SE, не Exchange Online; почта, календарь, контакты, занятость, GAL, приглашения.
Основной путь к Exchange — **EWS**; **IMAP/SMTP** — запасной для прочих ящиков, только почта. Стенда Exchange нет:
проверка — на боевом Exchange на тестовой учётной записи, по правилам раздела «Проверка на боевом Exchange».

Архитектура — `docs/adr/0003-backends-ews-imap.md` (предложение, ждёт решения владельца): нейтральная модель и
области-контракты в `core`, адаптер на каждый сервер, новые протокольные крейты L1 `ews` и `imap`. До решения по
ADR код не пишем; S7-04 (разведка сервера, только чтение) можно делать сразу после ответа о тестовой учётке.

Задача = ветка `s7/NN-кратко` = один PR. Проверка — тесты, снимки `--screens` (светлая и тёмная тема), стенд
Stalwart (JMAP и IMAP), боевой Exchange (тестовая учётка); руками — владелец по `docs/manual-tests/<задача>.md`.

## Цели

- Учётная запись Exchange: вход по адресу (Autodiscover), на машине в домене — без пароля (Kerberos от учётной
  записи Windows), иначе NTLM паролем; Basic по TLS — если включён на сервере.
- Почта Exchange со всеми функциями S3–S6, которые сервер позволяет: папки, беседы, чтение, отправка, черновики,
  вложения, поиск, push, метки и категории, сроки, «Ждём», «Отменить» и «Отправить позже», S/MIME, общие ящики,
  «Взять в работу», правила, автоответ, архив.
- Календарь Exchange: виды S5-21, встречи с приглашениями, ответы, отмены, «Помощник планирования» по
  `GetUserAvailability`, календари коллег (S5-22) по правам Exchange.
- Справочник GAL: подсказки адресов, раздел «Контакты → Справочник», сертификаты S/MIME адресатов; личные контакты.
- Задачи Exchange (модуль S6) и поручения письмами iMIP Postman.
- Учётная запись IMAP/SMTP: только почта — папки, письма, отправка, метки (если сервер хранит ключевые слова),
  поиск, IDLE.
- Несколько учётных записей в одном окне (Stalwart, Exchange, IMAP) — если владелец примет вопрос 4.
- JMAP/Stalwart не теряет ничего: поведение и тесты стенда — как до S7.

## Вне сессии

- Exchange Online / Microsoft 365, Microsoft Graph, OAuth Azure AD; OAuth on-prem (ADFS, Modern Auth Exchange 2019
  CU13+/SE) — после S7, по запросу (вопрос 3).
- MAPI/HTTP, Exchange ActiveSync, Outlook Anywhere (RPC/HTTP) — не нужны: EWS покрывает функции.
- Автономная адресная книга (OAB, файлы LZX) — справочник по поиску (вопрос 13).
- Публичные папки, ресурсы (переговорные) с автоакцептом — после S7 (`FindPeople` по списку комнат — потом).
- Правка прав делегатов (`AddDelegate`, `UpdateDelegate`) и прав на папки — только показ.
- IMAP: календарь и контакты (CalDAV/CardDAV чужих серверов), ManageSieve, OAuth2 (XOAUTH2/OAUTHBEARER) — после S7
  (вопросы 12, 14).
- Exchange через его IMAP — только откат ADR (если EWS закрыт).

## Покрытие IMAP/SMTP

| Область | Статус | Где / почему |
|---|---|---|
| IMAP4rev1 / IMAP4rev2 (RFC 3501, 9051), TLS 993 и STARTTLS | используется | S7-16; без TLS — не входим |
| `LOGIN` / `AUTHENTICATE PLAIN` | используется | S7-16 (пароль или пароль приложения) |
| `XOAUTH2` / `OAUTHBEARER` (RFC 7628) | запланировано | после S7, под конкретного провайдера (вопрос 12) |
| `IDLE` (RFC 2177) | используется | S7-16: push «Входящих» отдельным соединением; перезапуск раз в 29 мин |
| `CONDSTORE` / `QRESYNC` (RFC 7162) | используется | S7-16: дельты по `HIGHESTMODSEQ`, `VANISHED`; без них — сверка UID и флагов окном |
| `MOVE` (RFC 6851) | используется | S7-16; без него — `COPY` + `\Deleted` + `UID EXPUNGE` |
| `UIDPLUS` (RFC 4315) | используется | S7-16: UID после `APPEND`/`COPY`, `UID EXPUNGE` |
| `SPECIAL-USE` (RFC 6154) | используется | S7-16: роли папок; без него — по именам (ru/en) |
| `ENABLE` (RFC 5161), `ID` (RFC 2971) | используется | S7-16 (`ENABLE QRESYNC`; `ID` — только имя клиента) |
| Ключевые слова (`PERMANENTFLAGS \*`) | используется | S7-17: `pm.*` и категории; без `\*` — только в кэше |
| `QUOTA` (RFC 9208) | используется | S7-17: квота в настройках |
| `THREAD=REFERENCES` (RFC 5256) | используется, если есть | S7-17; без него — цепочки клиентом |
| `SEARCH` (TEXT, FROM, SUBJECT, SINCE) | используется | S7-17 + свой индекс tantivy |
| `LITERAL+`, `COMPRESS=DEFLATE`, `BINARY` | не нужно | выигрыш мал |
| `NOTIFY` (RFC 5465) | не нужно | редко у серверов; IDLE + `STATUS` |
| `METADATA` (RFC 5464) | не нужно | таблица категорий — локальный файл |
| ManageSieve (RFC 5804) | запланировано | после S7 |
| SMTP submission 587 STARTTLS / 465 TLS (RFC 6409, 8314) | используется | S7-16 (`mail-send`) |
| SMTP AUTH PLAIN / LOGIN | используется | S7-16 |
| SMTP AUTH XOAUTH2 | запланировано | вместе с IMAP OAuth2 |
| Копия в «Отправленные» (`APPEND`) | используется | S7-17; отключается, если сервер кладёт копию сам (настройка учётки) |
| FUTURERELEASE (RFC 4865) у SMTP | используется, если объявлен | S7-17: «Отправить позже» сервером; иначе — клиент |
| DSN (RFC 3461) | не нужно | — |

## Проверка на боевом Exchange

Стенда Exchange нет (решение владельца 2026-10-23): тесты — на боевом Exchange компании, «в разумных пределах», на
тестовой учётной записи. Правила обязательны для тестов и для ручных проверок агентов.

- **Только тестовые учётки.** Тестовая учётка `user1`; при необходимости — вторая тестовая `user2` и тестовый общий
  ящик (вопрос 10). Чужие ящики — только для чтения занятости.
- **Без массовых операций.** Тесты по одному, запросы — последовательно (не больше 1 одновременно, не чаще 5 в
  секунду), пачки — до 20 объектов, не больше 2 подписок на уведомления сразу (и отписка в конце). `ErrorServerBusy`
  — пауза `BackOffMilliseconds` и не больше 2 повторов, затем тест падает с понятным текстом.
- **Уборка после каждого теста.** Всё, что тест создаёт, — с меткой в теме `[postman-test <id прогона>]`;
  страж уборки удаляет созданное (письма, события, задачи, контакты, папки, категории, правила) и при падении теста.
  Отдельный тест `cleanup_leftovers` удаляет забытое по метке — только в тестовых ящиках.
- **Письма — только между тестовыми учётками.** Функция теста `test_recipient()` пропускает только адреса из
  окружения (`POSTMAN_EWS_USER*`, общий тестовый ящик); любой другой адрес — паника до отправки. Приглашения и
  поручения — так же.
- **Ничего общего для организации.** Правила, автоответ, делегаты, категории, права папок — меняются только у
  тестовых учёток; настройки организации, транспорт, политики, чужие ящики — не трогаем. Командлетов Exchange и
  прав администратора у тестов нет.
- **GAL и занятость коллег — только чтение:** `ResolveNames` по конкретной строке (до 10 результатов), `FindPeople` —
  одна страница, `GetUserAvailability` — до 3 адресов на окно до недели; без выгрузки справочника целиком.
- **Секреты и адрес сервера** — только из локального окружения или локального файла владельца (вне репозитория):
  `POSTMAN_EWS_URL` (или `POSTMAN_EWS_EMAIL1` для Autodiscover), `POSTMAN_EWS_USER1`, `POSTMAN_EWS_PASSWORD1` (без
  пароля — Negotiate от учётной записи Windows), `POSTMAN_EWS_USER2`/`PASSWORD2`, `POSTMAN_EWS_SHARED`,
  `POSTMAN_EWS_PEERS` (адреса коллег для занятости). В репозиторий, журнал, вывод тестов и описание PR не попадают
  ни адрес сервера, ни домен, ни имена: тесты печатают только счётчики и коды; `tracing` в `ews` скрывает адреса,
  `ItemId` и тела (уровень `debug` — тоже).
- **Тесты — `#[ignore]` и по окружению**, как у Stalwart: `crates/core/tests/stand_exchange*.rs`, запуск —
  `cargo test -p postman-core --test stand_exchange -- --ignored --test-threads=1` (шапка файла). Без окружения
  тесты пропускаются; CI их не запускает.
- **Корпус ответов** (`crates/ews/tests/fixtures/*.xml`) — записанные ответы, обезличенные (домен →
  `example.test`, имена → `user1`…); тест `fixtures_have_no_stand_names` (с окружением) проверяет, что в корпусе нет
  домена и адресов из `POSTMAN_EWS_*`.
- **Находки** — `docs/EXCHANGE.md` (как `docs/STALWART.md`: поведение, версии, ограничения; без адресов и имён);
  чего сервер не умеет — раздел «Пробелы» там же.

IMAP проверяется на стенде Stalwart (его IMAP и SMTP submission, `docs/STALWART.md`): `crates/core/tests/stand_imap.rs`,
переменные `POSTMAN_STAND_IMAP`, `POSTMAN_STAND_SMTP` и пользователи стенда [проверить: порты IMAP/submission
открыты наружу контейнера].

## Общие правила задач

- Как в S5–S6: цвета — роли темы, тексты — Fluent (`accounts.ftl` и части экранов, оба языка), действия — команды
  реестра, модальных окон нет.
- Поведение JMAP не меняется: каждый PR S7, трогающий `core::sync`, — с прогоном тестов стенда Stalwart.
- Чужие данные — только в воркере: `MimeContent`, тела IMAP, вложения, .ics. Разбор XML EWS и ответов IMAP — в
  `core`/L1 без DTD и с пределами размера; входы — в фаззинг.
- Демо-ящик (`demo`) получает учётки Exchange и IMAP (с их `Features`) — для снимков и `--bench`.
- Новое поведение Exchange — сначала тестом в `crates/core/tests/stand_exchange*.rs` по правилам «Проверка на
  боевом Exchange», находки — в `docs/EXCHANGE.md`.
- Бюджеты `docs/HANDOFF.md` §2c не ухудшаются: `--bench` до и после в описании PR; размер exe — в PR S7-05, S7-16,
  S7-18.

| № | Вопрос | Рекомендация |
|---|---|---|
| 1 | Принять ADR 0003: нейтральная модель и области в `core`, адаптер на сервер, `Backend` перечислением, крейты L1 `ews` и `imap`? | Да — вариант Б: JMAP-фасад хрупок, отдельные `core` дублируют логику |
| 2 | EWS-клиент: свой тонкий (quick-xml + hyper) или `ews` Thunderbird (MPL-2.0, только почта, без транспорта)? | Свой: из ~35 нужных операций у `ews-rs` около половины, вход, Autodiscover и уведомления всё равно свои; `ews-rs` — справочник по схемам, код не копируем |
| 3 | Вход на Exchange | Negotiate (Kerberos) от учётной записи Windows — основной, без пароля; NTLM паролем — для машин вне домена; Basic — только если включён; OAuth (ADFS) — после S7 |
| 4 | Несколько учётных записей в одном окне (Stalwart + Exchange + IMAP) | Да: дерево папок на учётку, как общие ящики сейчас; без этого запасной IMAP «для прочих ящиков» не имеет смысла |
| 5 | Срок письма (`pm.due`) на Exchange — как флаг Outlook «К исполнению» с датой? | Да: коллеги в Outlook на том же ящике видят срок; `$flagged` без срока — флаг без даты; остальные `pm.*` — только своё расширенное свойство |
| 6 | Категории: писать таблицу Postman в главный список категорий Outlook? | Да, с ближайшим из 25 цветов Outlook; категории Outlook вне таблицы показываются как есть (серым) и попадают в таблицу при первом выборе в Postman |
| 7 | «Отменить» и «Отправить позже» на Exchange | «Отменить» — держит клиент 10 с; «Отправить позже» — отложенная доставка сервера, если S7-04 подтвердит; иначе клиент с подписью «отправится, если Postman запущен» |

## Не проверено

Пункты [проверить] этой спеки и ADR 0003 закрывает S7-04 (боевой Exchange) и S7-16 (IMAP на стенде): Autodiscover
JSON, Basic на EWS, `ProposeNewTime`, отложенная доставка на сервере, квота, онлайн-архив, условия по расширенным
свойствам, `ItemClass` S/MIME при `CreateItem` с `MimeContent`, CONDSTORE/QRESYNC в `async-imap`, XOAUTH2 в
`mail-send`, порты IMAP стенда. Отключение EWS Microsoft касается Exchange Online, не Exchange Server
[проверить по объявлению Microsoft на дату S7-05].
