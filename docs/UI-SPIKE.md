# egui или gpui — сравнение на одном экране

Дата: 2026-10-17, протокол — 2026-10-18. Оба варианта используют одно ядро (хранилище, IR, воркер-песочница, демо-ящик);
отличается только крейт интерфейса: `app` (egui 0.37, wgpu) и `app-gpui` (gpui-kit 0.7.3 = gpui-pre 0.3.9 + gpui-component).

## Запуск

```sh
cargo build --release --workspace
target/release/postman      --demo --bench        # egui
target/release/postman-gpui --demo 50000 --bench  # gpui
```

Тестовая сборка под Windows: `scripts/build-windows.sh` → `dist/Postman-test-win64.zip`, внутри `bench.cmd`.

## Протокол сравнения (Windows)

Решение принимается по этой таблице. Колонки «Windows/Intel» заполняются из `bench.txt` и ручной проверки.

### Версии и подключение

| | egui | gpui |
|---|---|---|
| Крейты | egui, eframe, egui-winit 0.37.0; egui-wgpu → wgpu 30.0.1; winit 0.30.13 | gpui-kit 0.7.3 = gpui-pre 0.3.9 + gpui-component 0.7.3 |
| Откуда | crates.io, без патчей | crates.io. `gpui-pre` — снимок репозитория Zed (`zed@93d7456`), не официальный выпуск gpui (на crates.io официальный gpui — 0.2.2, с gpui-pre несовместим). gpui-kit и gpui-component — longbridge |
| Патчи | нет | `third_party/gpui-pre-windows`: шейдеры встроены в exe и компилируются при запуске (кросс-сборка из Linux без fxc.exe); `third_party/xattr` — только для Linux |
| Рендер на Windows | wgpu → DirectX 12 (Vulkan, GL — флагом) | собственный, DirectX 11 + DirectComposition |

### Измерения

`bench.cmd` прогоняет одинаковый сценарий: прогрев → 400 кадров листания с открытием письма в каждом кадре →
120 кадров ресайза → 3 с на успокоение и 10 с простоя. Ящик — 50 000 писем, общий файл для обеих версий;
перед замерами — холостой прогон, чтобы создание демо-ящика не попало ни в чей «первый кадр».
Обе версии рисуют с вертикальной синхронизацией (у egui её можно выключить флагом `--no-vsync`, у gpui — нет).

| Поле `bench.txt` | Что значит | egui DX12 | egui Vulkan | gpui |
|---|---|---|---|---|
| размер exe | release, mingw, коммит 4eb4c26 | 25,8 МиБ | ← | 19,0 МиБ |
| `first_frame_ms` | от запуска процесса до первого кадра | | | |
| `scroll_p50` / `scroll_p99` / `scroll_max` | интервал кадра при листании, мс (vsync 60 Гц = 16,7) | | | |
| `scroll_cpu_pct` | загрузка CPU процессом при листании, % одного ядра | | | |
| `resize_p50` / `resize_p99` / `resize_max` | интервал кадра при программном ресайзе, мс | | | |
| `rss_peak_mb` | пик рабочего набора за сценарий | | | |
| `idle_rss_mb` | рабочий набор в простое после сценария | | | |
| `idle_cpu_pct` | CPU в простое (окно открыто, ввода нет) | | | |

Оговорки:
- Размер exe не равнозначен: в egui-версии всё приложение (синхронизация, поиск tantivy, окно письма, адресная книга),
  в gpui-спайке — только список, чтение и календарь.
- `ui_cpu_p50/p99` между фреймворками не сравнивать: в egui это весь кадр интерфейса (раскладка и тесселяция),
  в gpui — только построение дерева элементов в `render()`.
- Память: `rss` — рабочий набор (Working Set), как столбец «Память» в диспетчере задач на вкладке «Подробности».

### Ручная проверка

| Проверка | egui DX12 | egui Vulkan | gpui |
|---|---|---|---|
| Развернуть / восстановить (двойной щелчок по заголовку, Win+↑/↓): чёрный кадр, мерцание | | | |
| Тянуть за край и угол: чёрные или рваные кадры, отставание содержимого | | | |
| Перетащить окно между мониторами с разным масштабом | | | |
| Хоткеи в русской раскладке: Ctrl+E, Ctrl+1/2, Ctrl+Q/Ctrl+U, j/k (на клавишах «о»/«л») | | — | |
| Хоткеи окна письма в русской раскладке: Ctrl+N/R/Shift+R/F (только egui) | | | — |
| Чёткость текста: кириллица, полужирный, мелкий кегль | | | |

Ожидание по коду (подтвердить руками):
- **egui** — хоткеи в русской раскладке должны работать: `egui-winit` при нелатинской букве берёт физическую клавишу
  (Ctrl+«к» = Ctrl+R).
- **gpui** — риск: на Windows клавиша сочетания берётся через `MapVirtualKeyW(…, MAPVK_VK_TO_CHAR)`, то есть
  символ текущей раскладки; сработает ли `ctrl-e` при русской раскладке, не очевидно. Если нет — нужен свой
  перевод виртуальных кодов клавиш в латиницу (ещё один патч gpui).

### Что не понравилось при разработке

**gpui**
- Нет стабильного выпуска: официальный gpui на crates.io отстаёт от Zed, рабочий вариант — снимок `gpui-pre`
  через стороннюю сборку gpui-kit. Версии между собой несовместимы, обновление = правка кода.
- Документации почти нет: API и компоненты разбирались по исходникам gpui-component и примерам Zed.
- Сборка: много зависимостей и долгая компиляция; кросс-сборка под Windows требует fxc.exe из Windows SDK —
  обошли патчем. Первая тестовая сборка упала на машине тестировщика: отладочный путь читал шейдеры по пути
  машины сборки. На Linux пришлось патчить `xattr`.
- Ошибки компиляции тяжело читать из-за обобщённых типов элементов.

**egui**
- Immediate mode: сложные экраны (строка письма, абзац со ссылками, календарь с наложением событий) — ручная
  геометрия. Нет полужирного и выравнивания внутри абзаца без своей раскладки текста.
- Перерисовывается весь интерфейс в каждом кадре — следить за ценой кадра на больших списках.
- Документация и примеры хорошие, API стабильный, сборка без сюрпризов (основной вес — wgpu).
- Vulkan на Intel даёт чёрный кадр при ресайзе — поэтому по умолчанию DX12.

## Что видно в контейнере (программный рендер, не для решения)

| | egui | gpui |
|---|---|---|
| Рендер на Windows | wgpu → DX12 (Vulkan по флагу) | собственный, DirectX 11 |
| Рендер на Linux | wgpu → GL (Vulkan по флагу) | только Vulkan |
| Первый кадр, 50 тыс. писем | 0,6–1,4 с | 0,76–0,80 с |
| Память | 163–178 МБ | 199–211 МБ |
| Полужирный, курсив, выравнивание в абзаце со ссылками | нет (нужен отдельный шрифт и своя раскладка) | да, текстовым движком |
| Раскладка | ручная (immediate mode) | flexbox (taffy), стили в духе Tailwind |
| Перерисовка | весь интерфейс каждый кадр | только изменившиеся представления (`cx.notify`) |
| Хоткеи | вручную в цикле кадра | действия + раскладки с контекстом, декларативно |
| Готовые компоненты | базовые | 60+: поле ввода с IME, таблица, календарь, дерево, диалоги |
| Доступность (экранный диктор) | AccessKit | AccessKit (в gpui-pre) [проверить на Windows] |
| Стабильность API | высокая, 0.x с регулярными релизами | низкая: gpui 0.2.2 и gpui-pre 0.3.9 несовместимы между собой |

Интервал кадра в этих ранних замерах не сравним: gpui был ограничен частотой виртуального дисплея (48 мс), egui мерился без vsync.

## Сложность разработки

- **egui** хорош для простых панелей, но всё сложнее списка требует ручной геометрии: строка письма нарисована
  примитивами, абзац со ссылками — набором отдельных меток (нет переноса внутри ссылки, нет выравнивания).
  Календарь с наложением событий и «Помощник планирования» потребуют своей раскладки поверх immediate mode.
- **gpui**: экран написан как дерево `div()` с flex-свойствами, абзац — один `StyledText` с выделениями,
  ссылки — диапазоны того же текста. Минусы: мало документации, компоненты разбираешь по исходникам,
  при обновлении ломается API, пришлось патчить зависимость `xattr` (несовместима со свежим `libc`).

## Самый сложный экран: календарь и «Помощник планирования» (gpui)

`app-gpui/src/calendar.rs`, 264 строки: рабочая неделя с раскладкой пересекающихся событий по колонкам
(абсолютное позиционирование с долями ширины), панель помощника — сетка занятости участников по 30 минут,
выбор дня и длительности, список общих свободных окон с подсветкой выбранного в сетке.
Собрался с первой попытки. Логика (раскладка, занятость, поиск окон) — в `crates/calendar` и общая для любого UI.
Ctrl+2 — календарь, Ctrl+Shift+Q — помощник.

## Предварительный вывод

Для интерфейса уровня Outlook (календарь, планировщик, богатый текст) gpui даёт заметно меньше собственного кода
и лучшее качество текста. Цена — нестабильный API и чуть больше памяти. Решение — после проверки на Windows/Intel:
ресайз без чёрных кадров, плавность листания, память.
