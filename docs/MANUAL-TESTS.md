# Ручные проверки (Windows)

Сюда собирается то, что проверяет только владелец руками: окно, ввод, поведение ОС. PR с ручной проверкой
добавляет раздел и строку в «Статус разделов». Проходим в диалоге: агент даёт команду и шаги, владелец отвечает
отметкой; итог — в «Результат» и, если что-то не так, отдельным PR.

**Порядок.** PR мержится после зелёного CI; ручная проверка — после мержа, по одной сборке со всеми
непроверенными разделами.

**Сборка.** `C:\Users\a.antropov\Documents\Claude\2026 FileNav\Postman\target\release\postman-gpui.exe`
(`cargo build --release -p postman-gpui`). Демо-ящик — `%LOCALAPPDATA%\Postman\demo.redb`.

## 1. Живой ресайз (S1-04)

Тянуть край и угол окна: содержимое не отстаёт, чёрной полосы нет.

## 2. Снимки экранов (S2-05)

`postman-gpui.exe --screens <каталог>` — пять PNG без участия человека.

1. Запустить с каталогом, например `%TEMP%\postman-screens`. Ожидание: окно появляется и само закрывается,
   в каталоге `list.png`, `letter.png`, `search.png`, `calendar.png`, `assistant.png`; код выхода 0.
2. Открыть снимки. Ожидание: каждый — настоящее окно (не чёрный, не пустой) и тот экран, что в имени.
3. `--screens … --lang en`. Ожидание: те же экраны по-английски.

## 3. Язык интерфейса (S2-06)

1. Запустить без `--lang`. Ожидание: язык — как у Windows (русский).
2. `--lang en`. Ожидание: все надписи по-английски: строка команд, папки, область чтения, строка состояния,
   календарь и помощник планирования (дни недели, легенда).
3. `--lang ru`. Ожидание: всё по-русски, сырых ключей вида `nav-mail` нигде нет.

## 4. Один экземпляр (S2-06)

1. Запустить Postman, свернуть окно.
2. Запустить второй раз (ярлыком или из проводника). Ожидание: второе окно не появляется; первое
   разворачивается и выходит на передний план, справа сверху тост «Postman уже запущен — показано это окно».
3. Закрыть Postman, запустить снова. Ожидание: обычный старт.
4. `--bench` при открытом Postman. Ожидание: замер идёт в своём окне (замеры не подчиняются правилу).

## 5. Журнал Windows (S2-06)

1. `postman-gpui.exe --demo abc --screens Z:\нет\такого` (недоступный каталог). Ожидание: выход с кодом 1.
2. «Просмотр событий» → «Журналы Windows» → «Приложение», источник `Postman`, код 1000. Ожидание: ошибка
   с текстом о сбое запуска (Windows допишет, что описание события не найдено, — источник регистрирует установщик).
   Из PowerShell (фильтр `ProviderName` для незарегистрированного источника не работает):
   `Get-WinEvent -LogName Application -FilterXPath "*[System[Provider[@Name='Postman']]]" -MaxEvents 3 | % { $_.Properties.Value }`
3. Паника: из `pets` — `cargo run -p pets-shell --example probe -- panic`. Ожидание: в журнале запись
   источника `PetsProbe` с текстом паники и местом в коде.

## 6. Тосты и история уведомлений (S2-06)

1. В поиске (Ctrl+E) ввести `zzzzqqq`, Enter. Ожидание: справа сверху тост «Ничего не найдено: «zzzzqqq»»;
   фокус остаётся в поле поиска — можно сразу печатать.
2. Подождать ~4 с. Ожидание: тост исчез сам.
3. Ещё 4 раза подряд — пустой поиск. Ожидание: на экране не больше трёх тостов, новый сверху.
4. Щёлкнуть тост. Ожидание: закрылся, письмо под ним не выбралось.
5. Щёлкнуть 🔔 в строке состояния. Ожидание: справа панель «Уведомления», новые сверху, со временем;
   счётчик 🔔 обнулился. Esc — панель закрылась (поиск при этом не сбросился).
6. В простое с открытой панелью и без неё — CPU ~0 % (Диспетчер задач).

## 7. Окно письма (S3-01)

Демо: `postman-gpui.exe --demo 2000`.

1. Ctrl+N. Ожидание: окно «Новое сообщение», курсор в «Кому»; основное окно листается (j/k).
2. В «Кому» 2+ буквы имени из демо-ящика. Ожидание: подсказки; ↓/↑ — выбор, Enter или щелчок — «Имя <адрес>; ».
3. `petr@corp`. Ожидание: красная рамка, строка «Не распознаны адреса: petr@corp».
4. Тема. Ожидание: заголовок окна — тема.
5. `**жирный**`, Ctrl+Shift+P. Ожидание: предпросмотр с полужирным; ещё раз — редактор.
6. «Вложить» — два файла; ✕ — убрать; перетащить файл из Проводника. Ожидание: чипы с именем и размером.
7. Ctrl+Enter (в тексте и в «Кому»), Alt+S. Ожидание (демо): строка «Не отправлено…», тост «Нужна учётная запись…»,
   текст на месте, перевода строки от Ctrl+Enter нет.
8. Esc с изменениями. Ожидание: «Сохранить черновик? Да / Нет / Отмена»; «Отмена» — строка ушла, «Нет» — окно
   закрылось. Окно без изменений — Esc закрывает сразу.
9. Через 60 с после правки. Ожидание: строка «Черновик не сохранён…», без тоста.
10. Закрыть основное окно при открытом окне письма. Ожидание: без падения.
11. На стенде (раздел 9 — вход): письмо user2 уходит, приходит, черновик сохраняется в «Черновики».

## 8. Область чтения: вложения, картинки, приглашения (S3-03)

1. Демо, письмо «Re: Совещание…». Ожидание: логотип внутри текста, в полосе вложений — `Итоги Q3.xlsx`.
2. «Открыть». Ожидание: открылось приложением. «Сохранить как» — диалог; у файла метка «из Интернета»
   (`Get-Content файл -Stream Zone.Identifier` → ZoneId=3), тост «Сохранено».
3. Письмо с `invoice.pdf.exe`. Ожидание: только «Сохранить», «Открыть» нет.
4. Письмо с приглашением. Ожидание: карточка (когда, где, организатор, участники), `invite.ics` в полосе нет;
   «Принять» в демо — тост «нужен сервер», статус не меняется.
5. Листать письма стрелками. Ожидание: картинки и карточка — от текущего письма.
6. На стенде: вложение скачивается и открывается; «Принять» на приглашении от user1 — тост, статус на карточке,
   после перезапуска статус тот же; у организатора — «принято».

## 9. Живой ящик на стенде (S3-04)

Туннель к стенду поднят (или прямой доступ), `%LOCALAPPDATA%\Postman\account.json` удалён, окружение без `POSTMAN_*`.

1. Запуск без `--demo`. Ожидание: строка входа на месте списка, курсор в «Сервер».
2. Сервер `http://localhost:18080`, `user1@itt.test`, неверный пароль. Ожидание: «Вход не выполнен: … 401».
3. Верный пароль. Ожидание: папки и письма стенда, внизу «Синхронизировано».
4. `account.json` — только адрес и логин; «Диспетчер учётных данных» → `Postman:http://localhost:18080:user1@itt.test`.
5. Перезапуск. Ожидание: сразу ящик.
6. Открыть непрочитанное — прочитано и на сервере; Insert — флаг на сервере.
7. От user2 письмо user1. Ожидание: появляется без перезапуска (push), выделение не прыгает.
8. Поиск по слову из темы. Ожидание: результаты; Esc — обратно к папке.
9. Остановить туннель. Ожидание: тост об ошибке синхронизации один раз; ящик читается из кэша.
10. `--sign-out`. Ожидание: строка входа, запись в диспетчере удалена. `--demo` — демо-ящик.
11. Окно в покое. Ожидание: ЦП ~0 %.
