# Учётные записи, файлы и связь с Подиумом — целевая схема

Дата: 2026-10-17. Статус: принятые направления, детали прорабатываются.
Пометки: [решение] — принято владельцем; [предложение] — к обсуждению; [проверить] — выяснить на стенде.

## 1. Решения

- Провайдер входа — **Authentik** (OIDC/SAML, LDAP-выход, RADIUS, MFA). Kanidm — запасной вариант, к нему
  возвращаемся, если Authentik не устроит по надёжности или поддержке. [решение]
- **MS AD выводится** после переноса почты на Stalwart. [решение]
- Рабочие станции — **MDM** вместо домена и групповых политик. [решение]
- Файловые ресурсы AD заменяются **Подиумом** (документы объектов: Сделка, Проект, договор…)
  и **Nextcloud** (общие и личные файлы). [решение]
- Postman ↔ Подиум — вариант **1+2**: клиент обращается к REST Подиума, Подиум показывает переписку
  в карточках. Детали — позже. [решение]

## 2. Кто за что отвечает

| Данные | Источник истины | Как попадает к остальным |
|---|---|---|
| Сотрудник: ФИО, должность, отдел, даты приёма и увольнения | Подиум, кадры (BP-23) | API Подиума → Authentik |
| Учётная запись, группы, пароль, MFA, сессии | Authentik | OIDC для приложений, LDAP для старых систем |
| Почтовый ящик, календарь, контакты | Stalwart | вход через Authentik [проверить: OIDC-каталог Stalwart] |
| Общие и личные файлы | Nextcloud | вход и группы из Authentik |
| Документы объектов Подиума | Подиум | вход через Authentik |
| Рабочая станция | MDM | регистрация под учётной записью Authentik |
| Реестр активов и доступов | Подиум (BP-26) | исполнители — Authentik и MDM |

Главный принцип: приложения знают только Authentik (OIDC). Смена каталога за ним (AD → собственная
база Authentik) приложений не касается.

## 3. Жизненный цикл сотрудника [предложение]

```
Подиум: приём (BP-23)  ──ЛТ──►  Authentik: пользователь + группы по должности и отделу
                                    ├─► Stalwart: ящик и календарь при первом входе
                                    ├─► Nextcloud: учётная запись и папки отдела при первом входе
                                    └─► MDM: регистрация рабочей станции
Подиум: увольнение     ──ЛТ──►  Authentik: блокировка, отзыв сессий и токенов
                                    ├─► Stalwart: вход закрыт, ящик сохранён, пересылка руководителю
                                    ├─► Nextcloud: передача файлов руководителю
                                    └─► MDM: вывод устройства, очистка корпоративных данных
```

Каждая цепочка — логическая транзакция по правилу 7 Подиума: состояния
ожидает → отправляется → отправлено → ошибка → сдался видны в карточке сотрудника.

## 4. Что учесть в Подиуме [предложение для Cowork]

Процессы BP-23 и BP-26 в модели есть, но сейчас шаги ручные («системный администратор создаёт учётную
запись в Подиуме»), а в коде их нет. Предложения — файлы `docs/bp/` правит Cowork:

1. **Вход в Подиум через Authentik (OIDC)** вместо собственных паролей; TOTP переходит в Authentik.
   Роль по должности = группа Authentik → роль Подиума.
2. **BP-23, шаги «учётные записи к первому рабочему дню» и «блокировка не позднее последнего дня»** —
   выполняет автомат через ЛТ в Authentik, человек только подтверждает. Сисадмин — на ошибках ЛТ.
3. **BP-26, «реестр активов и доступов» и «пересмотр доступов»** — Подиум сверяет фактические группы
   Authentik и устройства MDM с должностью; расхождения — в перечень на пересмотр.
4. **Кадровый модуль** (сотрудник, должность, отдел — `team.go`, `departments.go`, `personnel.go`) —
   источник для Authentik. Нужны даты приёма и увольнения и связка «сотрудник ↔ учётная запись».
5. **Файлы объектов** — объектное хранилище объявлено в каноне, но не развёрнуто
   (открытый вопрос в `docs/model-dump/questions.md`); с отказом от файловых ресурсов AD это становится обязательным.
6. **Postman** — новый набор прав API-токена (scope) для привязки письма к Сделке, Заявке, Сервисной заявке
   и контакту CRM; вкладка «Переписка» в карточках.

## 5. Переход [предложение]

1. Развернуть Authentik с AD как источником пользователей. Stalwart, Подиум, Nextcloud, Postman — сразу на OIDC.
2. Перенести почту в Stalwart.
3. Authentik — главный каталог: отключить синхронизацию с AD, учётные записи создаёт ЛТ из Подиума.
4. LDAP- и RADIUS-потребители (адресная книга Thunderbird, принтеры, Wi-Fi, VPN) — на Authentik.
5. Файлы — в Nextcloud и Подиум; рабочие станции — в MDM.
6. Выключить AD.
