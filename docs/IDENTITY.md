# Учётные записи, файлы и связь с системой учёта — целевая схема

Дата: 2026-10-17. Статус: принятые направления, детали прорабатываются. Отложенный модуль: сейчас
в фокусе почтовый клиент под Stalwart.
Пометки: [решение] — принято владельцем; [предложение] — к обсуждению; [проверить] — выяснить на стенде.

Обозначения: **IdP** — провайдер входа (OIDC/SAML, LDAP-выход, RADIUS, MFA); **система учёта** —
внутренняя учётная система компании (сотрудники, клиенты, сделки, документы); **файловое облако** —
общие и личные файлы.

## 1. Решения

- Вход во все приложения — через **IdP** по OIDC; выбран и запасной вариант. [решение]
- **MS AD выводится** после переноса почты на Stalwart. [решение]
- Рабочие станции — **MDM** вместо домена и групповых политик. [решение]
- Файловые ресурсы AD заменяются **системой учёта** (документы объектов) и **файловым облаком**. [решение]
- Postman ↔ система учёта: клиент обращается к её REST API, система учёта показывает переписку
  в карточках объектов. Детали — позже. [решение]

## 2. Кто за что отвечает

| Данные | Источник истины | Как попадает к остальным |
|---|---|---|
| Сотрудник: ФИО, должность, отдел, даты приёма и увольнения | система учёта, кадры | API → IdP |
| Учётная запись, группы, пароль, MFA, сессии | IdP | OIDC для приложений, LDAP для старых систем |
| Почтовый ящик, календарь, контакты | Stalwart | вход через IdP [проверить: OIDC в Stalwart] |
| Общие и личные файлы | файловое облако | вход и группы из IdP |
| Документы объектов | система учёта | вход через IdP |
| Рабочая станция | MDM | регистрация под учётной записью IdP |

Главный принцип: приложения знают только IdP (OIDC). Смена каталога за ним приложений не касается.

## 3. Жизненный цикл сотрудника [предложение]

```
Система учёта: приём    ──►  IdP: пользователь + группы по должности и отделу
                                ├─► Stalwart: ящик и календарь при первом входе
                                ├─► Файловое облако: учётная запись и папки отдела
                                └─► MDM: регистрация рабочей станции
Система учёта: увольнение ──►  IdP: блокировка, отзыв сессий и токенов
                                ├─► Stalwart: вход закрыт, ящик сохранён, пересылка руководителю
                                ├─► Файловое облако: передача файлов руководителю
                                └─► MDM: вывод устройства, очистка корпоративных данных
```

Каждая цепочка — транзакция «всё или ничего» с видимыми состояниями
(ожидает → отправляется → отправлено → ошибка → сдался).

## 4. Что нужно от Postman

- Вход по OIDC через IdP (сейчас — пароль или токен Stalwart).
- Привязка письма к объекту системы учёта через её REST API с отдельным набором прав токена.
